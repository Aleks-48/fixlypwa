# Fixly — техническая приёмка 26 сентября 2026

## Результат

База PostgreSQL, сайт и API запущены. Ngrok направлен на сайт, webhook Telegram настроен. Рабочая база не очищалась: для проверки добавлены отдельная ОСИ «Fixly — техническая проверка» и три синтетических пользователя.

- Локальный сайт: http://127.0.0.1:3000
- Внешний адрес: https://legless-bennie-sheepish.ngrok-free.dev
- Запуск своего рабочего окружения: `START_FIXLY.bat`.
- Запуск распакованного тестового архива: `START_TESTER.bat`. Он использует отдельную БД на порту 5545.

## Что исправлено

1. **Изоляция ОСИ.** В рабочей БД политики RLS существовали, но были отключены у большинства таблиц. Это обнаружено при просмотре реального скриншота: новый председатель видел чужой дом. Миграция восстановила защиту 33 таблиц. Проверка запуска теперь контролирует колонки, обязательность полей, RLS и роль подключения. Без контекста ОСИ таблица домов недоступна.
2. **Схема базы.** Устранено старое ограничение `users.phone NOT NULL`, мешавшее аккаунтам только с email; согласованы значения по умолчанию. Сверка Prisma со схемой БД дала пустую миграцию. Предыдущие исправления `language` и `bank_ref` сохранены.
3. **Вход.** Проверка OTP, погашение кода, сохранение имени и создание сессии объединены в транзакцию. Конкурирующие запросы не используют один код дважды. Форма ждёт готовности JavaScript, а её резервный способ отправки — POST, чтобы пароль не попадал в URL.
4. **Документы и фотографии.** Новые загрузки хранятся вне `public`. Старые `/uploads/…` проходят через обработчик с авторизацией и проверкой прав. Файлы исключены из Docker-контекста и release-сборки. Мобильный клиент загружает вложения с Bearer-токеном только со своего сервера.
5. **Финансы и квитанция.** Убраны обращения к несуществующим полям. Квитанция вместо заглушки показывает реальные начисления, оплаты, переходящее сальдо и реквизиты; чужую квитанцию получить нельзя. Печать и сохранение PDF доступны через браузер.
6. **Импорт.** Импорт квартир использует существующие Owner/Account и RLS. Парсер выписок переведён с уязвимого `xlsx` на ExcelJS: XLSX и CSV поддерживаются; старый XLS необходимо пересохранить. Числовые даты Excel обрабатываются отдельно.
7. **Опросы.** API и страницы приведены к существующей модели Poll/PollOption/Vote. Проверяется дом жителя; одновременное переголосование сериализовано. Имитация юридической подписи удалена, старые юридические маршруты ведут в обычные опросы.
8. **Кабинет мастера.** Рейтинг, отзывы и портфолио берутся из базы. Демонстрационные заказы, фиктивная карта и ложное успешное сохранение убраны. Исправлен адрес API отклика. Работа в портфолио и отклик реально сохранены через интерфейс; изменение имени синхронизирует пользователя и анкету мастера.
9. **Telegram.** Завершённые `update_id` не обрабатываются повторно. При сбое сервер возвращает 503 для повторной доставки; сетевые вызовы ограничены по времени. Контакт другого человека не привязывается к отправителю.
10. **Запуск и резервирование.** Батник останавливает сервер перед копированием БД и файлов, применяет миграции, проверяет защиту, запускает сайт, ngrok и настраивает webhook. Резервная копия восстановлена в отдельную временную БД, затем эта временная БД удалена. Рабочие данные сохранены.
11. **Зависимости и сборка.** Обновлены зависимости и тестовый раннер; исправлены ошибки строгой типизации и линтера. Аудит npm: 0 известных уязвимостей на момент проверки.

## Что ещё требуется перед реальным запуском

- VPS и домен в Казахстане, HTTPS, резервирование вне рабочего компьютера и мониторинг. Ngrok остаётся временным тестовым адресом и требует работающего компьютера.
- Реальный эквайринг и проверка финансовых интеграций с поставщиками. Текущая онлайн-оплата — демо.
- Юридически значимые голосования и государственные интеграции — подключение партнёра по ADR-0007. Обычные опросы юридическую подпись не заменяют.
- Физическая проверка APK на Android и push-уведомлений, релизная подпись; сборка APK сама по себе этого не подтверждает. iOS не проверен на устройстве.
- Реальная карта заказов и геокодирование: демонстрационная карта удалена из рабочего кабинета, пока этих данных нет.
- Полный пользовательский пилот с председателем и жителями, проверка их реальных файлов и всех редких сценариев. Текущий браузерный прогон охватывает перечисленные сценарии, а не каждый экран и каждую функцию.

Временный код входа отображается только при прямом локальном доступе и в режиме разработки. В публичном ngrok-адресе и production-сборке код не раскрывается; используется настроенный канал доставки.
