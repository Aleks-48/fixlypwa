# Функции продукта

> Статус: DRAFT · Версия: 0.2 · Дата: 2026-07-01
> **Стратегия (решено Рахимом, 2026-07-01):** занимаем территорию Управдома — **полный
> функционал ОСИ-платформы** (голосования, отчёты, госбазы — всё нужно), но выигрываем на
> **удобстве**. WhatsApp **не заменяем** (никто из него не уйдёт); цель — **уменьшить нагрузку
> на председателя и головную боль жителей**. См. vision.md, competitors.md.

## 0. Дифференциатор — это UX, а не фичи (иначе «лучше» — пустой звук)

У Управдома функции уже есть (2 300+ ОСИ, госинтеграции, Digital ID). Значит выигрыш —
**только в удобстве**, и его надо сделать явным и измеримым, иначе он копируется. Принципы,
по которым проектируем каждую функцию:

1. **Онбординг без беготни.** Главная жалоба на Управдом — «много беготни». Регистрация ОСИ,
   заведение дома, приглашение жителей — минимум шагов, предзаполнение из госбаз где можно.
2. **Меньше ручной работы председателя.** Автоматизировать то, что он делает руками: отчёт —
   одной кнопкой; авто-напоминания должникам; массовые действия; импорт вместо ручного ввода.
3. **Самообслуживание жителей → меньше звонков председателю.** Житель сам видит баланс, платит,
   подаёт заявку и следит за статусом, читает объявления — не дёргает председателя.
4. **Сосуществование с WhatsApp, а не борьба.** Не заставляем жить в приложении: шлём в WhatsApp
   короткие ссылки/сводки, вход по телефону+OTP, ноль трения. WhatsApp остаётся, мы снимаем с
   него формальную нагрузку (официальные объявления, заявки со статусом, деньги, отчёты).
5. **Mobile-first PWA, скорость, простые экраны.** Меньше полей, понятные формулировки.

> Эти 5 принципов — и есть продукт. Функции ниже — у всех; побеждает исполнение.

Визуальный язык и навигационная карта — по макету Claude Design: см. `ui-redesign.md`
(синяя палитра #2E6BF0, Golos Text, сайдбар на desktop + таб-бар на mobile).

## 1. Полный функционал (парити с Управдомом + удобнее)

### A. Управление ОСИ и структурой дома
- Регистрация и ведение ОСИ (реквизиты, БИН), домов, квартир.
- Реестр жителей и собственников (Owner/Occupant), импорт из Excel (Q-012).
- Упрощённый онбординг (принцип 1).

### B. Коммуникация (снижает нагрузку/головную боль — НЕ заменяет WhatsApp)
- **Объявления** председателя: адресные (дом/подъезд/квартира), закрепление, отметки о прочтении.
- **Заявки жителей**: категория, фото, статус (принята → в работе → решена), тред, официальный след.
- **Инфо-раздел дома**: вывоз мусора, аварийные контакты, реквизиты, контакты председателя.
- **Библиотека документов**: нормативные акты, протоколы, договоры, техническая документация и отчёты дома (загрузка председателем, разграничение приватности `isPublic`).
- **Push-уведомления (PWA)** + отправка сводки/ссылки в WhatsApp (принцип 4).

### C. Голосования и собрания
- **Быстрые опросы (lite)** — неформальные, мгновенный подсчёт. **Без аккредитации** (Тир 1).
- **Легитимные онлайн-голосования собрания собственников** — по Приложению 1 к приказу № 163:
  кворум **>50%**, два порога решений (большинство участников / большинство от всех), ~20 типов
  вопросов, форматы явочный/заочный/электронный, протокол с **ЭЦП** председателя/секретаря/совета,
  идентификация собственника. ⚠️ Юридически значимое электронное голосование **разрешено только
  через аккредитованный «объект информатизации в сфере ЖКХ»** (закон, приказ № 172) → **Тир 2**,
  требует аккредитации/партнёрства (см. блок E, gov-integrations.md).

### D. Финансы, учёт и отчёты
- **Тарифы** по статьям (эксплуатация/целевой/кап.ремонт) и **массовые начисления** за период.
- **Учёт платежей**, задолженность раздельно по статьям (REQ-024).
- **Реестр расходов** с контрагентами + **банковские счета/остатки** (REQ-025/026).
- **Импорт банковской выписки** (Q-012) — ключ к «отчёт без ручного ввода».
- **Автогенерация обязательного месячного/годового отчёта** по утв. форме — см. `report-spec.md`
  (разморожена). Это главный автоматизатор нагрузки председателя.
- **Кабинет жителя**: баланс, история начислений/платежей, реквизиты/оплата.

### E. Идентичность и госинтеграции (высокий риск, долго — трек начинать рано)
Полная карта госсистем и план подключения — **`gov-integrations.md`**. Кратко:
- Вход жителя по **телефону + OTP** (ADR-0005) — лёгкий вход (Фаза 1).
- Единая дверь к госданным — **Smart Bridge** (`sb.egov.kz`); доступ **только по согласию**
  пользователя, без массовой выгрузки.
- **Верификация собственника** через регистр недвижимости (по ИИН авторизованного жителя).
- **ГБД ФЛ** (личность), **ГБД ЮЛ** (ОСИ по БИН), **реестр МЖД/ОСИ** (жилинспекция), **БМГ**
  (телефон↔ИИН).
- **Digital ID** (биометрия по лицу, OAuth2) + **облачная ЭЦП** (для легитимных голосований).
- ⚠️ Это не код, а **партнёрство + правовой доступ** (Закон №94-V, биометрия — ПДн особой
  категории). Вероятно самый твёрдый блокер; выяснять условия **рано** (Q-039, gov-integrations.md §4).

## 2. Дорожная карта + два тира (регуляторный барьер делит продукт)

🔴 **Ключевое разделение (gov-integrations.md):** легитимные голосования и доступ к госбазам
разрешены **только аккредитованному «объекту информатизации в сфере ЖКХ»** (приказ № 172).
Это делит продукт на два тира:

- **Тир 1 — БЕЗ аккредитации (строим и продаём сразу):** Фазы 1–2. Реальная ценность, гос-барьера нет.
- **Тир 2 — ТРЕБУЕТ аккредитации/партнёрства (за регуляторной вехой):** Фаза 3.

**Фаза 1 (Тир 1) — ежедневная ценность, удобнее Управдома:**
A (ОСИ/дом/квартиры/жители, вход телефон+OTP) + B (объявления, заявки, инфо, push) + быстрые
опросы (lite) + кабинет жителя с балансом/реквизитами. → снимает головную боль и звонки, без
тяжёлого учёта и без госдоступа.

**Фаза 2 (Тир 1) — автоматизация нагрузки председателя, главный «крючок»:**
D целиком: тарифы, начисления, платежи, расходы, банковские счета, **импорт выписки Kaspi**
(bank-import.md), **автоотчёт по форме** (report-spec.md, публичное+внутреннее представление).
→ **Не требует госдоступа** — отчёт формируется из выписки + начислений. Это то, за что платят.

**Фаза 3 (Тир 2) — юридически значимое + госинтеграции (за аккредитацией, долго):**
C (легитимные голосования) + E (верификация собственника, Digital ID/ЭЦП, ГБД). Требует статуса
объекта информатизации ЖКХ (аттестация ГТС, договор Smart Bridge) **или партнёрства**. Трек
начинать выяснять **уже в Фазе 1** (sandbox бесплатен, юрист, приказ № 172).

## 3. Из принятой архитектуры — в силе (не выброшено)
PWA + push (NFR-040/041), вход телефон+OTP (ADR-0005), RLS-мультитенантность (ADR-0006),
self-hosted в РК, монолит Next.js + Docker (ADR-0002/0003). Доменная модель — полная
(Osi/Building/Apartment/Account/Owner/Occupant/Tariff/Charge/Payment/Expense/BankAccount/
Counterparty/Report) + коммуникационные (Announcement/Request/Poll) + голосования (Meeting/Vote).

## 4. Риски (честно, один раз — дальше исполняем)
- **Объём.** Полный парити с гос-партнёрским Управдомом — очень много для одного; «просто
  удобнее» копируется инкумбентом. → нужен ещё и канал/доверие (гиперлокальный Кокшетау,
  vision.md) как второй ров помимо UX.
- **Госбазы/Digital ID (E).** Не код, а право/партнёрство; у Управдома это через гос-партнёра.
  Самый вероятный твёрдый блокер — начинать выяснять доступ рано (Q-039).
- **UX как единственный дифференциатор** держится, только если он радикальный и измеримый
  (принципы §0), а не «чуть приятнее».

## 5. Связанные вопросы
Q-035 (полный отчёт — да), Q-039 (госбазы/Digital ID — да, риск), Q-037/038 (голосования/заявки — да),
