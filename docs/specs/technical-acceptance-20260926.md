# Техническая приёмка Fixly — 26 сентября 2026

Дополнение при визуальной проверке: кабинет мастера показывает только реальные заявки, отклики, портфолио и рейтинг из БД. Демонстрационные точки карты, выдуманные отзывы и фиктивное успешное сохранение исключаются из рабочего кабинета. Публикация портфолио и редактирование имени должны сохраняться через API и показывать ошибку при отказе сервера.

Запрос: выполнить доступные технические исправления, запустить БД/сайт, войти под тремя ролями и сохранить реальные скриншоты.

- ACCEPT-001: успешный OTP используется ровно один раз даже при конкурентных запросах; пользователь, ФИО и сессия записываются в одной транзакции. Ошибка записи откатывает погашение кода. Неверные попытки сохраняются.
- ACCEPT-002: /uploads/** обслуживается только после авторизации, по правам на документ/заявку/публикацию. Новые файлы хранятся вне public, имеют владельца; старые ссылки сохраняются через защищённый обработчик. Подмена пути и выдача служебных метаданных запрещены.
- ACCEPT-003: Telegram возвращает ошибку при неудачной обработке, чтобы получить повторную доставку; завершённые update_id не исполняются повторно. Собственный контакт проверяется; сетевые вызовы ограничены таймаутом.
- ACCEPT-004: проверка схемы после миграций обнаруживает недостающие колонки до запуска сайта. Сценарий запуска сохраняет БД и файлы; восстановление резервной копии проверяется в отдельной базе.
- ACCEPT-005: выполнить текущие lint, typecheck, unit/integration, production build; integration работает только в БД _test, реальные SMS/email/Telegram не отправляются тестами. Исправления зависимостей выбираются по фактическому аудиту без принудительных несовместимых обновлений.
- ACCEPT-006: войти в браузере через штатные формы председателем, жителем, мастером; открыть основные экраны и сохранить скриншоты без секретов. При обнаружении ошибок исправить и повторить проверку.
- ACCEPT-007: отчёт содержит выполненные изменения, точные результаты и оставшиеся внешние зависимости. Обновить пакет исходников для тестирования после успешных проверок. VPS, реальные платежи и отправка сообщений третьим лицам без реквизитов/разрешения не имитируются.

Упаковка ACCEPT-002: после production-сборки удаляются только копии локальных .env и пользовательских загрузок внутри standalone. Рабочие файлы сохраняются; окружение production передаётся при запуске. Сальдо квитанции считается отдельно по назначению платежа: переплата одного фонда не погашает долг другого.

Уточнения по обнаруженным дефектам: импорт квартир использует существующий реестр Owner/Account и RLS; отсутствующую общую площадь не сохраняет молча. Квитанция включает реальные начисления, оплаты и переходящее сальдо, доступна только своему жителю. Обычные опросы используют Poll/PollOption/Vote и проверяют дом жителя; устаревшие экраны юридического голосования перенаправляются на обычные опросы, поддельные подписи не формируются. Мобильный клиент передаёт авторизацию при получении защищённых вложений. Обновление тестового раннера допускается с адаптацией конфигурации и полным прогоном существующих проверок.
