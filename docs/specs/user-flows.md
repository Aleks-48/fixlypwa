## F-1. Онбординг ОСИ (председатель)
1. **Self-service регистрация** председателя (Q-019 закрыт) — email/телефон + пароль (Chairman
   входит иначе, чем Resident — см. ADR-0005 §«Практические следствия»).
2. Создание ОСИ (реквизиты) и первого дома.
3. Ввод квартир: вручную / импорт из Excel — способ ввода остаётся открытым, см. Q-012 ниже.
4. Ввод собственников (Owner) и проживающих (Occupant с телефоном — Occupant не регистрируется
   сам, председатель заводит его карточку; вход по OTP становится доступен после этого —
   **Q-027 закрыт этим**: self-service только у председателя, житель — заводится председателем).
5. Настройка тарифов по статьям (эксплуатация/целевой/кап.ремонт — закрыто Q-008).
6. Активация подписки на дом, trial (единица — дом, закрыто Q-009).

## F-2. Начисление за период (председатель)
1. Выбор дома и периода (месяц).
2. Применение тарифов → генерация Charge по всем счетам.
3. Ручные корректировки/разовые начисления. [TBD, не блокирует MVP]
4. Фиксация начислений. Статусы Charge: **открыто → частично оплачено → оплачено → просрочено**
   (закрыто Q-023).

## F-3. Учёт платежей (председатель)
1. Ручной ввод платежа по лицевому счёту (сумма, дата) — эквайринга нет в MVP (см. vision.md, out of scope).
2. Импорт банковской выписки — способ ввода данных (ручной/импорт) остаётся открытым вопросом,
   **Q-012**: требует реального образца файла у председателя, не закрывается решением в чате.
3. Пересчёт баланса/задолженности — вычисляемое значение (закрыто Q-010).

## F-4. Генерация месячного отчёта (КЛЮЧЕВОЙ, председатель)
1. Выбор дома + период.
2. Система собирает **все 4 блока утверждённой формы**: остатки на счетах, задолженность,
   поступления (по категориям), расходы (с контрагентами) — не только начисления/платежи по
   квартирам. Полная структура — в `report-spec.md`. Юр. источник — приказ № 163
   (V2000020283, в ред. № 362/№ 380); приказ № 164/V2000020247 **утратил силу** 12.09.2025.
3. Формирование отчёта. Точный формат/шаблон (PDF/веб/оба), язык (казахский — обязателен по
   NFR-090), состав полей — **Q-013 остаётся открытым**: нужен реальный образец текущего
   Excel-отчёта председателя, чтобы не спроектировать это вслепую. Юр. форма отчёта задаёт
   минимальный состав, но не UX/формат вывода.
4. Публикация жителям (доступен весь отчёт дома — Q-018) / выгрузка файла.
> Цель успеха (из vision): < 5 минут на весь флоу.

## F-5. Кабинет жителя
1. Вход жителя — телефон + OTP (закрыто Q-020, ADR-0005).
2. Просмотр своих начислений и истории платежей.
3. Просмотр полного отчёта дома (закрыто Q-018).
4. PWA: офлайн-просмотр последних данных, установка на телефон.

## F-6. Установка PWA / офлайн
1. Add to Home Screen.
2. Офлайн-доступ к ранее загруженным данным (что именно кэшируем — [TBD, техническая деталь,
   уточняется при реализации service worker, не блокирует спеку).

## Открытые вопросы (остаются)
**Q-012** (формат/способ импорта данных — нужен реальный Excel-файл председателя) и
**Q-013** (формат/шаблон месячного отчёта — нужен реальный образец) — оба требуют внешнего
артефакта от живого председателя, не закрываются решением «в кабинете»; см. рекомендацию
в open-questions.md.
