# Спецификация: Модуль «Настройки» (Settings)

> Статус: DRAFT · Версия: 0.1 · Дата: 2026-07-23
> Архитектурное соответствие: ADR-0005 (Auth/Identity), ADR-0006 (Postgres RLS), docs/specs/domain-model.md

Модуль «Настройки» обеспечивает единую точку управления параметрами ОСИ, финансовыми реквизитами, командой управления домом, персональными данными пользователей, выбором языка и подписками на уведомления.

---

## 1. Структура модуля и распределение по ролям

### 1.1. Настройки ОСИ и дома (Роль: Председатель / `CHAIRMAN`)

Управление реквизитами ОСИ и параметрами дома доступно только Председателю в рамках тенанта (`osiId`) с соблюдением RLS.

1. **Юридические реквизиты ОСИ:**
   - Наименование ОСИ (например, *ОСИ «Абай 15»*).
   - БИН (12-значный Бизнес-идентификационный номер) — уникален в системе (`Osi.bin`).
   - Юридический и фактический адрес.
   - Дата государственной регистрации.

2. **Финансовые реквизиты (для отчётов по Приказу №163 и квитанций):**
   - **Текущий счёт** (управление и содержание): Наименование банка, БИК, IBAN (ИИК).
   - **Сберегательный счёт** (накопления на капитальный ремонт): Наименование банка, БИК, IBAN (ИИК).
   - *Примечание:* Учёт счетов ведается в сущности `BankAccount` (см. `REQ-026`, `report-spec.md`).

3. **Контактные данные для жителей:**
   - Телефон и график работы председателя.
   - Телефоны круглосуточной аварийной / диспетчерской службы (`InfoItemType.EMERGENCY_CONTACTS`).

4. **Управление командой дома (Права и доступ в рамках RLS):**
   - Приглашение и назначение участников: Бухгалтер (`ACCOUNTANT`), Управляющий / Член совета дома, Мастер.
   - Назначение ролей через `UserOsiRole` (при этом RLS изолирует доступ пользователей строго в рамках `activeOsiId`).

5. **Настройки тарифов по умолчанию:**
   - Базовый тариф на управление и содержание МЖД (₸/кв.м).
   - Базовый тариф на накопительный взнос на кап.ремонт (₸/кв.м, не менее 0.005 МРП по Закону о жилищных отношениях РК).

---

### 1.2. Профиль и персональные настройки (Роль: Житель / Все пользователи)

Персональные настройки относятся к уровню пользователя (`User`) и доступны каждому аутентифицированному пользователю.

1. **Персональные данные:**
   - ФИО (`User.fullName`).
   - Контактные данные: телефон, email.
   - Пароль (только для Председателя, `passwordHash`).

2. **Выбор языка интерфейса (Локализация):**
   - Переключение между **Русским (`ru`)** и **Казахским (`kk`)** языками интерфейса (`User.language`).

3. **Управление привязанными объектами (Квартиры/Помещения):**
   - Просмотр привязанных квартир (связь `Occupant` / `Owner` ↔ `Apartment`).
   - Подача заявки на привязку к новой ОСИ/квартире (`OsiJoinRequest`, `REQ-151`).

4. **Настройки Web Push и notification-каналов:**
   - Управление активными Web Push подписками (`PushSubscription`, `FcmToken`).
   - Гранулярные тумблеры включения/отключения категорий уведомлений:
     - Объявления дома (`ANNOUNCEMENT`).
     - Изменение статусов заявок (`REQUEST_STATUS`).
     - Новые начисления (`CHARGE_CREATED`).

## 2. API Контракты (Draft Endpoints)

Все эндпоинты требуют действующей сессии (`getCurrentAuth()`). Эндпоинты ОСИ проверяют роль через `chairmanContext()`.

### 2.1. Эндпоинты Председателя (ОСИ и Дом)

- **`GET /api/settings/osi`**
  - **Описание:** Получение полного профиля ОСИ, банковских счетов, текущих тарифов и списка команды.
  - **Уровень доступа:** Chairman (`chairmanContext`).
  - **Response (200 OK):**
    ```json
    {
      "osi": {
        "id": "uuid",
        "name": "ОСИ Абай 15",
        "bin": "123456789012",
        "address": "г. Кокшетау, ул. Абая, 15",
        "registeredAt": "2024-01-15T00:00:00Z"
      },
      "bankAccounts": [
        { "id": "uuid", "type": "CURRENT", "bankName": "Kaspi Bank", "accountNumber": "KZ123456789012345678" },
        { "id": "uuid", "type": "SAVINGS", "bankName": "Halyk Bank", "accountNumber": "KZ987654321098765432" }
      ],
      "team": [
        { "userId": "uuid", "fullName": "Иванов И.И.", "role": "CHAIRMAN", "phone": "+77011112233" }
      ]
    }
    ```

- **`PATCH /api/settings/osi`**
  - **Описание:** Обновление юридических и контактных реквизитов ОСИ.
  - **Уровень доступа:** Chairman (`chairmanContext`).
  - **Body:**
    ```json
    {
      "name": "ОСИ Абай 15 Обновленное",
      "bin": "123456789012",
      "address": "г. Кокшетау, ул. Абая, д. 15"
    }
    ```

- **`POST /api/settings/team`**
  - **Описание:** Назначение роли сотруднику/члену совета в ОСИ.
  - **Body:** `{ "userId": "uuid", "role": "ACCOUNTANT" }`

---

### 2.2. Эндпоинты Пользователя / Жителя

- **`GET /api/profile`**
  - **Описание:** Получение профиля текущего пользователя и его настроек.
  - **Response (200 OK):**
    ```json
    {
      "user": {
        "id": "uuid",
        "fullName": "Асан Пердешев",
        "phone": "+77771234567",
        "email": "asan@example.kz",
        "language": "ru"
      },
      "apartments": [
        { "apartmentId": "uuid", "number": "42", "buildingAddress": "ул. Абая, 15" }
      ]
    }
    ```

- **`PATCH /api/profile`**
  - **Описание:** Обновление личных данных и предпочтительного языка.
  - **Body:**
    ```json
    {
      "fullName": "Асан Пердешев",
      "email": "asan_new@example.kz",
      "language": "kk"
    }
    ```

- **`GET /api/notifications/preferences`**
  - **Описание:** Получение настроек подписок на уведомления.

- **`PATCH /api/notifications/preferences`**
  - **Описание:** Включение/отключение категорий push-уведомлений.
  - **Body:**
    ```json
    {
      "announcements": true,
      "requestUpdates": true,
      "charges": false
    }
    ```

## 3. Изменения в схеме данных (`web/prisma/schema.prisma`)

Для поддержки локализации и настроек уведомлений требуются следующие доработки модели:

### 3.1. Доработка модели `User` (Identity, ВНЕ RLS)
Добавление поля языка интерфейса (дефолт `ru`):
```prisma
model User {
  // ... существующие поля
  language     String   @default("ru") @db.VarChar(5) // 'ru' | 'kk'
  // ...
}
```

### 3.2. Доработка модели `Osi` (Identity, ВНЕ RLS)
Поля `bin` и `address` уже присутствуют в `schema.prisma`. Требуется уточнить опциональное поле `bik` или реквизиты банка в `BankAccount`.

### 3.3. Новая модель `NotificationPreference` (Tenant, ПОД RLS)
Для сохранения пользовательских настроек фильтрации уведомлений:
```prisma
model NotificationPreference {
  id               String   @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  osiId            String   @map("osi_id") @db.Uuid
  userId           String   @map("user_id") @db.Uuid
  announcements    Boolean  @default(true)
  requestUpdates   Boolean  @default(true)
  charges          Boolean  @default(true)
  createdAt        DateTime @default(now()) @map("created_at")
  updatedAt        DateTime @updatedAt @map("updated_at")

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([osiId, userId])
  @@index([osiId])
  @@map("notification_preference")
}
```

## 4. Ссылки на архитектурные решения (ADR)

- **ADR-0005 (Auth & Sessions):** Настройки профиля пользователя (`User`) не зависят от тенанта, но аутентификация опирается на единый токен сессии.
- **ADR-0006 (Postgres RLS):** Настройки ОСИ (`Osi`), банковские счета (`BankAccount`), тарифы (`Tariff`) и предпочтения уведомлений (`NotificationPreference`) изолированы по `osiId` в рамках активной сессии председателя/жителя через `forTenant()`.
