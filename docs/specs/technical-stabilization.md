# Техническая стабилизация Fixly

Дата: 2026-09-24. Объём: исправления текущего продукта перед локальным пилотом.

## Проверяемые требования

- TECH-001: PostgreSQL запускается из web/docker-compose.yml с сохранением тома; готовность подтверждается pg_isready.
- TECH-002: GET /api/clean-duplicate не изменяет данные и возвращает 410. Очистка требует отдельного административного процесса с предварительным просмотром.
- TECH-003: анализ документа получает его внутри forTenant(osiId); чужой документ не передаётся модели. Ошибка разбора ответа не должна утверждать юридическое соответствие.
- TECH-004: integration-тесты используют отдельную БД с суффиксом _test независимо от имени основной БД. Отсутствие URL или несовпадение имён останавливает запуск до изменения данных.
- TECH-005: при сбое распознавания фото API возвращает явную ошибку вместо выдуманного диагноза и уверенности.
- TECH-006: Prisma-схема соответствует существующим миграциям email-only и языка пользователя; TypeScript проверяет сборку. Vitest корректно разрешает пути на Windows.
- TECH-007: назначение мастера и отзыв используют контекст ОСИ; запрос другой ОСИ недоступен. API проверяют формат ввода и возвращают HTTP-ошибки вместо редиректов страниц.
- TECH-008: document_read, notification_preference и ikomek_complaint защищены RLS deny-by-default, как остальные tenant-таблицы. Новая миграция не удаляет данные.
- TECH-009: сохранение профиля действительно обновляет ФИО и язык согласно REQ-046/047; вход по email сохраняется.

Проверки: TypeScript, целевые unit-тесты, PostgreSQL; integration — только после проверки изоляции тестовой БД. Результаты и ограничения фиксируются в отчёте.
- TECH-010: недостающие поля и связи восстанавливаются миграциями без удаления исторических отзывов; публичные ответы отзывов не раскрывают телефон автора.
- TECH-011: Telegram привязывает номер для входа только при передаче собственного контакта в личном чате: contact.user_id, from.id и chat.id должны совпадать. Чужой контакт не изменяет привязку. При внешнем доступе OTP_DEV_ECHO=0.
- TECH-012: после обычного входа пользователь с анкетой мастера без членства в ОСИ попадает в /master, а не в создание ОСИ. Пользователи с членством сохраняют свой кабинет ОСИ.
- TECH-013: восстановительная миграция добавляет отсутствующую users.language с ru по умолчанию без удаления аккаунтов. Если существует прежняя колонка lang, её значения сохраняются. Вход по коду и паролю не должен падать с Prisma P2022.
- TECH-014: восстановить payment.bank_ref и expense.bank_ref и их уникальность внутри ОСИ без удаления платежей и расходов; вкладка финансов жителя открывается.
- TECH-015: при OTP_DEV_ECHO=1 код показывается на странице входа только в development/test для прямого запроса на loopback. URL, Host, Origin и переданные прокси адреса проверяются; внешний ngrok не получает код. В локальном режиме номер без Telegram-привязки получает код на странице; привязанный номер сохраняет доставку в Telegram.
