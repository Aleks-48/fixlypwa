# Админка платформы (срез 9)

> Статус: ACTIVE · Дата: 2026-07-07 · Основание: ADR-0008, build-plan-2 (срез 9), Q-053.
> Аудитория — только владелец платформы (мы). Desktop-first, русский. Тир 1.

## 1. Роли и доступ (REQ-110)

- **REQ-110 [MUST]** `/admin/**` и `/api/admin/**` доступны только пользователю с
  `User.isSuperadmin = true` (ADR-0008). Страницы: не вошедший → redirect `/login`;
  вошедший не-суперадмин → 404 (`notFound()`). API: 401 / 403 (`Errors.forbidden()`).
  Каждая мутация `/api/admin/**` пишет запись в `AdminAuditLog` (actor, action, entity, diff).
- Назначение суперадмина — только CLI `npm run make-superadmin -- <телефон>` (DIRECT_URL).
  Из веба флаг не мутируется. Вход — штатный (email+пароль или телефон+OTP).

## 2. Верификация мастеров (REQ-114, закрывает Q-053)

- **REQ-114 [MUST]** Экран `/admin/masters`: все анкеты мастеров (Master — identity, вне RLS)
  с фильтром по статусу, по умолчанию — PENDING первыми. Поля: ФИО, телефон, город,
  категории, о себе, дата подачи, статус.
- Действия: APPROVED / REJECTED / BLOCKED (любой → любой; повторное одобрение после BLOCKED
  допустимо). PATCH `/api/admin/masters/[id]` `{ status }`. Аудит: `MASTER_STATUS`.
- CLI `approve-master.ts` остаётся аварийным fallback (маркетплейс.md §3 обновлён этим фактом).

## 3. ОСИ и подписки (REQ-111)

- Экран `/admin/osi`: список всех ОСИ (identity) — название, БИН, дата, председатели
  (UserOsiRole CHAIRMAN/SUPERADMIN → users), число домов, сводка статусов подписок.
  Тенантные данные (дома, подписки) — через `forTenant(osiId)` после гейта (ADR-0008).
- **REQ-111 [MUST]** Карточка `/admin/osi/[id]`: дома ОСИ; на каждый дом — подписка
  (Q-009: единица подписки — дом): статус TRIAL/ACTIVE/PAST_DUE/CANCELED + период
  (periodStart/periodEnd). Создание (у дома ещё нет подписки) и смена статуса/периода:
  PUT `/api/admin/subscriptions` `{ osiId, buildingId, status, periodStart?, periodEnd? }`
  (upsert по buildingId). Аудит: `SUBSCRIPTION_SET`.
- Ограничения при PAST_DUE (functional.md REQ-071: блокируется только председатель,
  чтение жителя не страдает) — enforcement вне этого среза; здесь только управление статусом.

## 4. Аккаунты председателей (REQ-112)

- **REQ-112 [MUST]** В карточке ОСИ — «Добавить председателя»: телефон (обязателен,
  User.phone — первичный идентификатор) + email (опционально).
  - Телефон существует → добавить `UserOsiRole(CHAIRMAN, osiId)` (идемпотентно).
  - Телефона нет → создать User (+email, +временный пароль, если указан email) и роль.
  - Временный пароль генерируется, показывается **один раз** в ответе/UI; в аудит и логи
    не пишется. Аудит: `CHAIRMAN_GRANT` (без пароля в diff).
- «Сбросить пароль» у существующего председателя с email: новый временный пароль, показать
  один раз. POST `/api/admin/chairmen/[userId]/reset-password`. Аудит: `PASSWORD_RESET`.
  Сессии пользователя при сбросе отзываются (удаляются) — угнанная сессия не переживает сброс.

## 5. Дашборд (REQ-113)

- **REQ-113 [SHOULD]** `/admin`: счётчики платформы — ОСИ, пользователи, мастера по статусам
  (identity — одним запросом); дома, квартиры, активные заявки (сумма `forTenant`-циклом
  по ОСИ — приемлемо на целевом масштабе, ADR-0008). Ссылки на разделы.

## 6. Вне скоупа среза

Биллинг-платежи, импперсонация («войти как председатель» — риски аудита, отдельное решение),
метрики использования, enforcement PAST_DUE, удаление ОСИ/пользователей.

## 7. Модель данных (миграция среза)

- `users.is_superadmin boolean NOT NULL DEFAULT false` (identity).
- `admin_audit_log` (identity, вне RLS, append-only): id, actor_user_id, action (text),
  entity_id (text), diff jsonb null, created_at. Приложение не делает UPDATE/DELETE.

## 8. Definition of Done

- e2e: не вошедший → redirect; вошедший житель → 404 на /admin; суперадмин: одобряет
  PENDING-мастера через UI → мастер видит витрину (перепроверка флоу маркетплейса).
- integration: гейт adminContext (401/403/ok); смена статуса мастера пишет AdminAuditLog;
  upsert подписки виден через forTenant той же ОСИ и НЕ виден из чужой; создание
  председателя идемпотентно по роли.
- Все существующие тесты зелёные; `/code-review` + `/security-review` пройдены.
