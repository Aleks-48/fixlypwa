# Заявка жителя на подключение к ОСИ

> REQ-151..154 (`docs/requirements/functional.md`). Добавлено 2026-07-21 — заменяет
> устный/внеканальный обмен идентификатором (REQ-007 «сообщите председателю телефон/email»)
> на самообслуживание: житель сам находит ОСИ и подаёт заявку, председатель видит её в
> кабинете и уведомление, привязку делает как раньше.

## Поток

1. Пользователь без роли (`activeOsi === null`, `page.tsx`) видит поиск вместо инструкции.
2. Ищет ОСИ по названию/адресу (`GET /api/osi/search?q=`) — Osi вне RLS (identity, bootstrapping),
   поиск не требует tenant-контекста.
3. Выбирает ОСИ, вводит свободный текст «дом/квартира» (не Apartment — председатель не обязан
   иметь точный реестр к моменту заявки) и отправляет (`POST /api/osi/join-request`).
4. Председатели ОСИ получают in-app уведомление (REQ-100, `notifyOsiJoinRequest`).
5. Председатель открывает список заявок (`GET /api/osi/join-requests`, дашборд), видит контакт
   (телефон/email из User) и пометку жителя.
6. Председатель подключает жителя **существующим способом** — карточка нужной квартиры →
   «Житель» → тот же телефон/email (REQ-013, `AddResidentForm`/`addResident`). Заявка это не
   делает автоматически — председатель сам решает, к какой квартире привязать.
7. Председатель отмечает заявку обработанной (`POST /api/osi/join-requests/[id]/resolve`) —
   вручную, не привязано к фактической привязке (председатель мог отклонить/уточнить лично).

## Данные

`OsiJoinRequest` — identity-таблица (ВНЕ RLS, как `UserOsiRole`/`TelegramLink`): создаётся ДО
того, как у пользователя есть роль/tenant-контекст в этой ОСИ. Председатель читает её вручную
отфильтрованной по своей `osiId` (тот же паттерн, что `chairmenOfOsi()` в notifications/service.ts).

- `@@unique([userId, osiId])` — REQ-154, повторная заявка обновляет `note`/`status`, не дублирует.
- `status`: `PENDING` → `RESOLVED`. Нет `DECLINED` в MVP — председатель либо подключает, либо
  игнорирует/отмечает обработанной; жёсткий отказ не в объёме.

## Границы (осознанно вне объёма)

- Заявка не привязывает Apartment автоматически — это всегда ручное действие председателя
  (REQ-013 уже покрывает верификацию личности через существующий телефон/email).
- Нет отклонения с уведомлением жителю («заявка отклонена») — председатель может списаться
  напрямую (контакт уже виден в заявке).
- Нет ограничения «одна заявка на ВСЕ ОСИ разом» — пользователь может отправить заявки в
  несколько ОСИ параллельно (например, не уверен, какая именно его), `@@unique` только per-OSI.
