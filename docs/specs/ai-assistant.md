> Статус: DRAFT · Дата: 2026-07-22 (обновлено: решение по провайдеру)

> (data residency для внешнего AI). Старый план среза 30 («свой /api/ai → Gemini») —

> **провайдер выбирается через `LLM_PROVIDER`, как остальные внешние каналы проекта**
> (`SMS_PROVIDER`, `EMAIL_PROVIDER`, `TELEGRAM_PROVIDER`) — старт на **Groq** (бесплатный
> тариф, MVP-валидация), Claude API и self-hosted — готовые к переключению альтернативы
> (см. §4). Важно: смена провайдера НЕ снимает вопрос трансграничной передачи данных
> (Q-061/§6.3) — она одинаково касается любого внешнего API, бесплатного или платного.

## 1. Зачем и для кого

Две боли, которые ассистент закрывает без похода к председателю/в поддержку:

- **Житель**: «почему у меня долг 5 000?», «в каком статусе моя заявка?», «как подать
  заявку на ремонт?», «что говорит закон о целевых взносах?» — сейчас всё это либо звонок
  председателю, либо самостоятельный поиск по экранам.
- **Председатель**: «кто должники в доме?», «сколько собрали за июль?», «напиши объявление
  об отключении воды», «что означает статья 6.3 в отчёте по приказу №163?» — рутина, которую
  LLM делает за секунды и которая усиливает главный аргумент продажи (автоотчёты + удобство).

Не цель (вне рамок): юридические консультации с ответственностью (дисклеймер обязателен),
мутации данных от имени пользователя (MVP строго read-only), голосовой ввод.

## 2. Функции по ролям (MVP)

### Житель
| Функция | Как реализована |
|---|---|
| Мой долг / начисления / платежи | tool `get_my_balance`, `list_my_charges`, `list_my_payments` — поверх существующих `residentBalances`/`listResidentCharges`/`listResidentPayments` |
| Статус моих заявок | tool `list_my_requests` |
| Объявления дома | tool `list_announcements` |
| Помощь составить заявку | генерация черновика текста заявки из описания проблемы (без создания — даём кнопку «Создать заявку с этим текстом», подставляющую черновик в существующую форму) |
| Вопросы по закону об ОСИ / приказу №163 | RAG по корпусу нормативки (см. §7) |
| «Как пользоваться приложением» | системный промпт содержит краткую карту функций продукта |

### Председатель
| Функция | Как реализована |
|---|---|
| Финансовая сводка дома | tool `get_finance_summary` (начислено/оплачено/долг по бакетам) |
| Должники | tool `list_debtors` — номера квартир + суммы, **без ФИО** (см. §6) |
| Открытые заявки | tool `list_open_requests` |
| Черновики объявлений / ответов жителям | генерация (без tools) |
| Пояснения к отчёту №163 | RAG по приказу №163 + структура собственного отчёта |

Роль определяется существующим `memberContext`/`chairmanContext` — набор tools собирается
по роли на сервере, житель физически не получает председательских инструментов.

## 3. Архитектура

```
[Чат-виджет веб / Flutter ai_chat_screen]
        │  POST /api/assistant/chat (SSE-стрим, та же auth: cookie / Bearer + X-Client)
        ▼
[Next.js route handler, runtime nodejs]
        │  1. auth → роль → набор tools
        │  2. история диалога из БД (уже псевдонимизированная)
        │  3. скраббер входа (телефоны/email/ИИН из текста пользователя)
        ▼
[LlmProvider — адаптер (src/lib/assistant/providers/*), выбор через LLM_PROVIDER]
        │  tool call ──▶ существующие сервисы под forTenant/RLS ──▶ псевдонимизатор ──▶ tool result
        ▼
[SSE-дельты клиенту] → де-псевдонимизация при рендере → UI
```

Ключевые решения:

- **Провайдер за интерфейсом, как остальные внешние каналы проекта.** По аналогии с
  `SMS_PROVIDER`/`EMAIL_PROVIDER`/`TELEGRAM_PROVIDER` — `LLM_PROVIDER=groq|claude|console`
  (`console` — dev-заглушка без реального вызова, как у остальных каналов). Один интерфейс
  `LlmProvider` (`chat({ systemPrompt, messages, tools, signal }) → AsyncIterable<Delta>`),
  реализации `GroqProvider` (MVP-дефолт) и `ClaudeProvider` (готова, не включена). Ключ —
  server-side (`GROQ_API_KEY` / `ANTHROPIC_API_KEY`, НЕ `NEXT_PUBLIC_*`); без ключа выбранного
  провайдера фича выключена (graceful-off, как Web Push/FCM).
  ⚠️ Форматы у провайдеров разные не только в модели, но и в протоколе: Groq — OpenAI-совместимый
  `chat.completions` с `tools`/`tool_calls` (официальный `groq-sdk` для Node, либо `openai`-клиент
  с `baseURL` на Groq — уточнить на groq.com/docs при реализации 30a); Claude — Messages API с
  `tool_use`-блоками и Tool Runner (`@anthropic-ai/sdk`, `client.beta.messages.toolRunner`).
  Адаптер нормализует оба протокола к одному внутреннему формату дельт/tool-вызовов — именно
  поэтому tools/RAG-логика (§2, §5, §7) описана в терминах результата, а не привязана к SDK.
- **Tool use вместо «напихать данные в промпт»**: модель получает инструменты, вызывающие
  те же сервисы с тем же контекстом авторизации, что и обычные API-роуты. Это одновременно
  решает мультитенантность (RLS), права (роль), актуальность данных и размер контекста.
- **Streaming SSE** — паттерн уже есть в проекте (`/api/events`, срез 24); клиентский чат
  рендерит дельты текста по мере генерации, независимо от провайдера.
- **Prompt caching** — специфика Claude-адаптера (Anthropic `cache_control: {type: "ephemeral"}`
  на последнем блоке системного промпта; минимальный кэшируемый префикс на Opus 4.8 — 4096
  токенов). У Groq в MVP явного управления кэшем нет — экономия на этом провайдере не в фокусе,
  бесплатный тариф важнее. Если/когда переключимся на Claude — включить кэш по этому пункту.
- **История диалога** — в своей БД (см. §8), в псевдонимизированном виде; каждый ход
  отправляет полную историю (провайдеры в основном stateless), формат истории — внутренний,
  адаптер переводит его в протокол конкретного провайдера при вызове.

## 4. Модель, провайдер и стоимость

**Решение 2026-07-22**: старт на **Groq, бесплатный тариф** — MVP-валидация продукта без
счёта; переход на Claude (или self-hosted) — по факту жалоб на качество ответов/tool use
или упора в лимиты бесплатного тарифа, не заранее. Смена — конфигурация (`LLM_PROVIDER`),
не переписывание фичи (см. §3).

### 4.1. Groq (MVP-дефолт)

- Бесплатный тариф хостит открытые модели (на момент решения — семейства Llama 3.x/4,
  Qwen; конкретный актуальный список моделей и id уточнить на groq.com/docs при реализации
  30a — Groq регулярно меняет линейку и лимиты чаще, чем живёт этот документ).
- Бесплатный тариф лимитирован по запросам/токенам в минуту и в день (per-model, тоже
  смотреть в доке на момент реализации) — при реальной нагрузке нескольких ОСИ одновременно
  возможны 429; это ожидаемо для MVP-этапа, не повод паниковать, но повод мониторить
  (см. §9 лимиты — реюзаем ту же инфраструктуру для «ассистент временно перегружен»).
- **Известный риск качества** (осознанно принят): открытые модели заметно слабее Claude в
  (а) точности многошагового tool use — важно для сценариев «финсводка → должники → черновик
  объявления» за один диалог, (б) нюансах русского/казахского языка, (в) точном цитировании
  источников в RAG (§7). Если это станет заметно жителям/председателям — сигнал переключаться.

### 4.2. Claude API (резерв — качество, если Groq не устроит)

По текущему прайсу Anthropic (кэш: запись ~1.25×, чтение ~0.1× от input):

| Модель | ID | Input $/1M | Output $/1M | Комментарий |
|---|---|---|---|---|
| Claude Opus 4.8 | `claude-opus-4-8` | $5.00 | $25.00 | Лучшее качество на русском/казахском и в tool use — целевой вариант при переходе с Groq |
| Claude Sonnet 5 | `claude-sonnet-5` | $3.00 ($2 до 31.08.26) | $15.00 ($10) | Удешевлённый вариант, если Opus избыточен |
| Claude Haiku 4.5 | `claude-haiku-4-5` | $1.00 | $5.00 | Только для простых FAQ-маршрутов |

Прикидка стоимости диалога (6 ходов, системный промпт+tools ~5K кэшированы, история+tool
results ~3–6K/ход, ответы ~0.5–1K): **порядка $0.10–0.30 на Opus 4.8**. При 50 активных ОСИ
и ~20 диалогов/ОСИ/мес → ~1 000 диалогов ≈ **$150–300/мес**; на Haiku — в ~5 раз меньше. Этот
бюджет — точка сравнения, когда встанет вопрос «стоит ли платить за качество».

Параметры запроса на Claude-адаптере: `thinking: {type: "adaptive"}`,
`output_config: {effort: "low"|"medium"}` (чат-сценарий, латентность важна), `max_tokens`
~2–4K (стрим), `betas` только для tool runner.

### 4.3. Self-hosted (радикальная альтернатива, не MVP)

Открытые веса (Qwen/Llama) на своём VPS через Ollama/vLLM — единственный вариант, который
физически снимает вопрос трансграничной передачи (данные не покидают инфраструктуру).
Не MVP: нужен GPU-VPS (дороже текущего 2vCPU/4GB из `docs/deploy.md`), качество на CPU
неприемлемо для чата в реальном времени. Держим в уме как путь, если юр. заключение по
§6.3 окажется жёстким («никакой внешний API недопустим ни при каких условиях»).

## 5. Мультитенантность и права

- Каждый tool внутри вызывает существующий сервис через `forTenant(osiId, …)` /
  identity-запросы **с контекстом текущей сессии** — ассистент не имеет собственного
  доступа к данным и физически не может прочитать чужой тенант (RLS deny-by-default).
- Набор tools собирается по роли (`memberContext` → жительские, `chairmanContext` → +
  председательские). Пользователь без роли получает только RAG/FAQ.
- MVP: **все tools read-only**. Никаких мутаций (создание заявок/платежей/объявлений) от
  имени модели — генерация черновиков отдаётся в UI, действие совершает человек кнопкой.

## 6. Анонимизация (ядро Q-061)

Прод-ограничение проекта — ПДн физически в РК. Вызов внешнего LLM API (Groq, Claude — не
важно какого, см. §6.3) — передача данных за границу, поэтому граница «наш сервер →
провайдер» проектируется так, чтобы **прямые идентификаторы физлиц туда не попадали**:

### 6.1. Псевдонимизатор (модуль `src/lib/assistant/pseudonymizer.ts`)

- **Tool results** перед попаданием в контекст LLM проходят замену:
  - ФИО жителей/заявителей → стабильные псевдонимы «Житель-1», «Заявитель-2» (словарь
    замен — per-conversation, хранится в строке диалога; стабильность важна и для смысла,
    и для байт-идентичности префикса → кэш);
  - телефоны/email → маски (уже есть `maskPhone`/`maskEmail`);
  - ИИН, номера лицевых счетов, банковские реквизиты — **не включаются в tool results
    вообще** (фильтр на уровне самих tools, не пост-обработка);
  - номера квартир и суммы — остаются (без ФИО не идентифицируют физлицо; председателю
    «кв. 5 — долг 25 000 ₸» — рабочий ответ);
  - адрес дома — остаётся (адрес объекта/юрлица ОСИ, не ПДн физлица).
- **Вход пользователя** — регекс-скраббер на телефоны/email/ИИН в свободном тексте
  (пользователь может сам вписать «мой номер +7701…») — заменяются масками до отправки.
- **Ответ модели** де-псевдонимизируется при рендере (обратный словарь) — пользователь
  видит настоящие имена, провайдер (Groq/Claude) — нет.
- Контакты председателя (InfoItem) в контекст не передаются: ассистент отвечает ссылкой
  на раздел «Инфо дома».

### 6.2. Хранение и логи

- В `AssistantMessage` хранится **псевдонимизированный** текст + словарь в
  `AssistantConversation.pseudonymMap` (jsonb). Дампы/логи диалогов не содержат прямых ПДн;
  история между ходами воспроизводится байт-в-байт (кэш).
- Серверные логи — только метрики (токены, латентность, tool-вызовы), не содержимое.

### 6.3. Юридическая рамка (открытый вопрос, НЕ блокирует MVP-разработку)

- Техническая псевдонимизация ≠ автоматическая юридическая «обезличенность» по закону РК
  «О персональных данных и их защите» (трансграничная передача). До прод-запуска фичи —
  юр. заключение (новый Q в open-questions). Дополнительно: согласие пользователя при
  первом открытии чата (чекбокс) + пункт в пользовательском соглашении.
- ⚠️ **Этот пункт одинаково применим к любому провайдеру из §4** — Groq, Claude и любой
  другой внешний API одинаково являются трансграничной передачей данных за пределы РК;
  «бесплатно» и «открытая модель» тут ни при чём (открытость лицензии модели не влияет на
  то, где физически исполняется инференс — у Groq это тоже чужая инфраструктура, не наша).
  Смена провайдера в §4 — вопрос стоимости/качества, а не решение этого пункта.
- Радикальная альтернатива при жёстком юридическом требовании — self-hosted (см. §4.3):
  локальная LLM на своём VPS в РК, тогда трансграничной передачи просто нет.

## 7. RAG — где нужен, где нет

**Не RAG (tool use):** живые данные тенанта — балансы, заявки, объявления. Они маленькие,
структурированные и меняются — векторный индекс тут вреден.

**RAG (корпус нормативки):**
- Приказ №163 (PDF уже в `docs/reference/`), Закон РК «О жилищных отношениях» (публичный
  текст), FAQ продукта. Это **публичные тексты без ПДн** — их передача внешнему API
  беспроблемна, а чанки можно хранить как угодно.
- Таблица `normative_chunk` (вне RLS: id, source, article, text, tsvector) — чанки по
  400–800 токенов с реквизитами статей.
- **MVP: полнотекстовый поиск Postgres** (`to_tsvector('russian', …)`), tool
  `search_regulations(query)` → топ-5 чанков → модель цитирует с реквизитами
  («ст. 50 Закона о жилищных отношениях»). Ноль новой инфраструктуры — в духе проекта.
- **Фаза 2 (если качества FTS не хватит):** pgvector в том же Postgres + локальная
  модель эмбеддингов (bge-m3/multilingual-e5 в контейнере на VPS — данные не покидают
  сервер; у Anthropic API эмбеддингов нет, внешний Voyage — лишняя зависимость).
- **Фаза 3 (после среза 32 «Библиотека документов»):** RAG по документам ОСИ (уставы,
  протоколы) — чанки под RLS (osi_id), скоуп через forTenant.

## 8. Модель данных

```prisma
/// Диалог с ассистентом — tenant-таблица ПОД RLS (osiId сессии на момент создания).
model AssistantConversation {
  id           String   @id ...
  osiId        String
  userId       String
  title        String?          // первые слова первого вопроса
  pseudonymMap Json             // {"Житель-1": {...ссылка на occupantId...}} — де-подстановка при рендере
  createdAt    DateTime
  messages     AssistantMessage[]
}

model AssistantMessage {
  id             String  @id ...
  osiId          String
  conversationId String
  role           String  // user | assistant
  content        String  // ПСЕВДОНИМИЗИРОВАННЫЙ текст
  toolCalls      Json?   // имена вызванных tools + аргументы (аудит, без результатов)
  tokensIn/Out   Int?    // для бюджета
  createdAt      DateTime
}
```

Пользователь без роли (нет osiId): MVP — диалог не сохраняется (stateless чат), либо
отдельное решение позже.

## 9. Лимиты, злоупотребления, безопасность

- **Rate limit**: по паттерну `rateLimit.ts` (durable, по счётчику в БД) — например
  30 сообщений/сутки на пользователя, 300 на ОСИ; при превышении — понятная ошибка.
- **Бюджет**: суммарные `tokensIn/Out` пишутся в AssistantMessage → дневной/месячный
  стоп-кран на организацию (env-переменная, $-лимит), админка платформы видит расход.
- **Prompt injection**: содержимое заявок/объявлений — недоверенный пользовательский текст,
  попадающий в контекст через tool results. Митигтакция: (а) tools строго read-only —
  максимум вреда от инъекции: кривой ответ; (б) tool results оборачиваются маркерами
  «данные, не инструкции» в промпте; (в) системный промпт явно инструктирует игнорировать
  инструкции внутри данных.
- **Ошибки**: адаптер провайдера нормализует ошибки в общий вид (`RATE_LIMITED` → «попробуйте
  позже», `PROVIDER_UNAVAILABLE` → «ассистент временно недоступен») — конкретные классы
  исключений `groq-sdk`/`@anthropic-ai/sdk` уточняются при реализации 30a, наружу утекает
  только нормализованный код; graceful-off без ключа выбранного провайдера.
- Дисклеймер в UI: «Ответы сгенерированы ИИ и могут содержать ошибки; не является
  юридической консультацией».

## 10. UI

- **Веб**: плавающая кнопка в кабинете → шторка чата (Sheet, как MobileMenu). Стрим текста,
  чипы-подсказки по роли («Мой долг», «Статус заявок» / «Должники», «Сводка за месяц»),
  markdown-рендер, кнопка «Создать заявку с этим текстом» у черновиков. История диалогов —
  список в шторке.
- **Flutter**: `ai_chat_screen` уже существует за фича-флагом (наследие Fixly, целился в
  Gemini) — перенацеливается на `/api/assistant/chat` (тот же Bearer, SSE-парсер уже есть
