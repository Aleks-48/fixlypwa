# Спека: единый визуальный стиль сайта и приложения («шалфей и песок»)

> Статус: ACTIVE · Дата: 2026-07-17 · Основание: решение Рахима 2026-07-17.
> **Superseded:** `ui-redesign.md` (синий #2E6BF0 по макету Claude Design) — палитра той
> ревизии заменяется этой спекой; структурные решения (сайдбар/таб-бар, навигационная карта,
> AppShell) остаются в силе, меняется только визуальный язык.

## 1. Решение

Канон визуального стиля — **основная тема Flutter-приложения fixly**
(`fixly/lib/theme/app_theme.dart`, класс `AppColors`, 21 экран): палитра «шалфей и песок»,
светлая + тёмная. Сайт (`fixlypwa`) переделывается под неё. Обоснование выбора (из
комментариев самой темы, совпадает с нашей аудиторией): контрастный зрелый шалфей — «для
хорошей читаемости пожилыми», мягкий хвойно-чёрный текст — «комфортнее чистого чёрного»;
председатели ОСИ и жители — возрастная аудитория (features.md §0).

Вторая дизайн-система приложения (тёмно-синий #0A0E1A + #4361EE, захардкожена на 6 экранах:
splash, login, register, mobile_home_stub, income, Master_Detail) — **упраздняется**, экраны
приводятся к AppColors.

⚠️ **Контраст (аудитория — пожилые, NFR):** в light-теме primary для текста/кнопок — именно
`#6B7A47` (контраст с белым ≈ 4.6:1, WCAG AA), НЕ воздушный `#8A9A5B` (≈3:1 — только для
крупных элементов/заливок). Тема приложения уже различает их — сайту повторить, не упрощать
до одного значения. Soft-подложки (`--accent`, `--success-soft`…) пересчитать от новой
палитры (light — светлые тона песка/шалфея; dark — alpha, как сейчас, без slash-модификаторов
поверх — известная грабля).

## 3. План работ (срезы, трек U в build-plan-3 §12а)

- **U1 — эта спека + ревизия ui-redesign.md** (плашка superseded). ✅ этим документом.
- **U2 — сайт: подмена токенов.** `src/app/globals.css`: значения `:root`/`.dark` по таблице
  §2.1 (структура переменных НЕ меняется — вся разводка shadcn/Tailwind остаётся); PWA
  `theme_color`/иконки под новую палитру; пересчёт soft-токенов; прогон обеих тем глазами
  (скриншоты light/dark ключевых экранов: лендинг, /login, дашборд председателя, кабинет
  жителя, /admin); e2e полный (селекторы не цветовые — регресса не ждём, но проверяем).
  DoD: ни одного «синего #2E6BF0» пикселя; контраст текстов AA. Объём: 1–2 д.
- **U3 — приложение: снос второй дизайн-системы.** 6 хардкод-экранов → AppColors:
  `splash_screen`, `login_page`, `mobile_home_stub` — по ходу среза 22 (они и так
  переписываются/заменяются); `register_page` — умирает в срезе 22; `income_screen`,
  `Master_Detail_Page` — при переносе соответствующих функций (срезы 22/25). Отдельного
  среза НЕ нужно — это правило для всех срезов 22+: **новые/переносимые экраны — только
  AppColors.of(context), хардкод цветов запрещён**. Объём: внутри срезов 22/25.
- **U4 — сайт: полировка вне токенов.** Места, где цвет зашит мимо переменных (градиенты
  лендинга, иллюстрации, email-шаблоны кодов, favicon/иконки PWA, печатная форма отчёта —
  отчёт по приказу №163 НЕ перекрашивать, он документ); финальные скриншоты. Объём: 1–2 д.

Порядок: U2 — сразу (сайт получает новый вид одной правкой токенов), затем срез 22
(приложение, экраны сразу на AppColors, правило U3), U4 — после U2 в любой момент.

## 4. Что осознанно НЕ делаем

- Не переносим Golos Text в приложение и не меняем шрифт сайта (§2.2).
- Не перекрашиваем печатную форму отчёта №163 — это официальный документ.
- Не трогаем структуру навигации (сайдбар/таб-бар из ui-redesign.md остаются).
- Тема по умолчанию на сайте — system (как сейчас, next-themes); dark-принудительно не делаем.
