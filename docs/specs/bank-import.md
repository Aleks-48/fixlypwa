# Спека: Импорт банковской выписки (Kaspi Pay) → расходная часть отчёта

> Статус: DRAFT · Версия: 0.1 · Дата: 2026-07-01
> Закрывает банковскую половину Q-012 (расходы для отчёта, Фаза 2). Структура выписки —
> по данным Рахима (реальный формат Kaspi Pay). ⚠️ Точные названия колонок/парсинг —
> подтвердить на реальном PDF-файле выписки перед написанием парсера.
> **Важно: импорт выписки НЕ требует госдоступа/аккредитации** — это Фаза 2, строится сразу.

## 1. Шапка выписки Kaspi Pay (ЛК → Мой Банк → Выписка → PDF)
Обязательные реквизиты:
- Клиент (наименование ОСИ), **БИН**
- Период (с … по …)
- **Номер счёта (IBAN)**, валюта (KZT)
- **Входящий остаток** на начало периода
- **Всего зачислено** (поступления)
- **Всего списано** (расходы)
- **Исходящий остаток** на конец периода

→ Входящий/исходящий остаток напрямую питают строки 1–2 отчёта (остатки на счетах).
→ Одна выписка = один `BankAccount` (текущий или сберегательный).

## 2. Таблица транзакций → строки отчёта (Приложение 3)
Каждая расходная операция: **Дата · Тип операции · Получатель/Назначение · Сумма · [статья отчёта]**.
Задача импорта — разложить транзакции по строкам 7.1.1–7.6. Примеры маппинга:

| Назначение платежа (пример) | Статья отчёта |
|---|---|
| ТОО «…-РЭК», за электроэнергию ОДН | 7.4 Коммунальные услуги (ОДН) |
| ИП «…», акт №, ремонт кровли (материалы) | 7.3 Текущий ремонт общего имущества |
| ТОО «Лифт-Сервис», ТО лифтов | 7.2.1 Обслуживание лифтов |
| Перечисление ЗП председателя/бухгалтера | 7.1.1 / 7.1.2 Оплата труда |
| УГД (ОПВ, СО, ВОСМС, ИПН) | 7.1.3 Обязательные платежи в бюджет |
| Kaspi Bank, комиссия за РКО | 7.1.4 Банковские услуги |

## 3. Правила интеграции (обязательные, из практики)
1. **Комиссия банка** — любое списание Kaspi за переводы юрлицам/РКО заносится **отдельной
   строкой** «Банковские услуги» (7.1.4). Не прятать внутри других сумм.
2. **Переводы на Kaspi Gold физлицам** (разовый подрядчик без ИП): в отчёте — **сумма перевода +
   удержанный ИПН 10%**; назначение платежа должно ссылаться на **ДГП** (договор ГПХ). Модель
   расхода должна поддерживать пару «выплата физлицу + удержанный налог».
3. **Совпадение итогов до тиына:** «Всего списано» в выписке = итог раздела «Расходы» (блок 7)
   в отчёте. Импорт обязан давать сверку и подсвечивать расхождения.
4. **Внутренние переводы** («перевод собственных средств» между текущим и сберегательным
   счётом) — помечать `isInternalTransfer`, исключать из доходов/расходов (иначе задвоение).
5. **Хранение:** оригинал PDF-выписки подшивается как первичный документ, доступен совету дома/
   ревизкомиссии по требованию → в модели `Report`/`BankStatement` хранить ссылку на исходный файл.

## 4. Следствие для модели (domain-model.md)
- `BankStatement`: id, bankAccountId, период, входящий/исходящий остаток, всего зачислено/списано,
  ссылка на PDF-оригинал, статус сверки.
- `Expense` дополняется: `withheldTax` (ИПН при выплате физлицу), `contractRef` (ДГП/договор/акт).
- Импорт — это **сопоставление** (reconciliation): транзакция выписки → предложенная статья
  (эвристика по назначению) → подтверждение председателем. Полностью авто-классификация — Q-012
  (нужен корпус реальных выписок, чтобы обучить правила); MVP — правила + ручное подтверждение.

## 5. Что ещё нужно (Q-012, остаток)
- **Реальный PDF-файл выписки Kaspi Pay** от председателя — подтвердить точные колонки/формат
  (Kaspi может отдавать PDF/Excel/CSV — уточнить, что реально выгружается).
- **Excel с квартирами/жителями** — для доходной части (начисления), отдельно от выписки.
