# Документация проекта ОСИ (SDD)

Работаем по **Spec-Driven Development**: сначала спека/требование → потом код со ссылкой на номер.

## Структура

```
/docs
  /specs           — «зачем» и «что»: продуктово-доменный слой
    vision.md          — корневой документ, точка отсчёта
    domain-model.md    — сущности и связи предметной области
    glossary.md        — термины ОСИ/КСК (рус/каз), юр. определения
    user-roles.md      — роли и матрица доступа
    user-flows.md      — ключевые пользовательские сценарии
    report-spec.md     — структура месячного отчёта (ключевая фича) + приватность (публично/скрыто)
    bank-import.md     — импорт выписки Kaspi Pay → расходная часть отчёта (Q-012)
    competitors.md     — конкурентный ландшафт (Управдом, eOSI, e-Knot), стратегические выводы
    features.md        — набор функций (полный охват + удобство), фазы 1–3
    gov-integrations.md— карта госсистем РК (Smart Bridge, ГБД, Digital ID, ЭЦП, БМГ), блок E
    ui-redesign.md     — редизайн UI (shadcn/ui, светлая/тёмная темы, мобильная навигация)
    marketplace.md     — маркетплейс мастеров: витрина заявок, отклики, приватность (ADR-0009)
    admin-panel.md     — админка платформы: мастера, подписки, председатели (ADR-0008)

  /requirements    — проверяемые требования
    functional.md      — функциональные (REQ-XXX)
    non-functional.md  — нефункциональные (NFR-XXX)
  /adr             — architecture decision records (расширенный MADR)
    ADR-template.md
    ADR-0001..N.md
  api-contracts.md — контракты API-routes
  open-questions.md— СВОДНЫЙ реестр открытых вопросов (Q-XXX)
```

Единый источник модели данных — `/prisma/schema.prisma`. `domain-model.md`
описывает домен на языке предметной области; schema.prisma — его техническая реализация.

## Соглашение о маркерах (важно)

Заглушки и незакрытые решения помечаются единообразно, чтобы их можно было найти grep-ом:

| Маркер | Значение |
|---|---|
| `[TBD]` | Значение/решение ещё не определено (inline) |
| `> ❓ Q-XXX:` | Открытый вопрос. Дублируется в `open-questions.md` под тем же номером |
| `> ⚠️ ДОПУЩЕНИЕ:` | Рабочее допущение, принятое «пока», требует подтверждения |
| `Статус: DRAFT \| REVIEW \| APPROVED` | Зрелость документа (в шапке) |
| `Proposed \| Accepted \| Superseded` | Статус ADR |

Правило: **любой `[TBD]` и `❓ Q-XXX` в тексте должен иметь запись в `open-questions.md`.**
`open-questions.md` — единая точка правды по нерешённому; отдельные документы на него ссылаются.

## Нумерация

- Требования: `REQ-001`, `REQ-002`, … (функциональные); `NFR-001`, … (нефункциональные).
- Решения: `ADR-0001`, … (4 цифры, не переиспользуются даже после Superseded).
- Вопросы: `Q-001`, … (не переиспользуются; закрытые помечаются RESOLVED, не удаляются).
- В коде и тестах ссылаемся комментарием: `// REQ-042`.
