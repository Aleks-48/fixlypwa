# API-контракты

> Статус: STUB · Версия: 0.2 · Дата: 2026-07-01
> Заполняется по мере проработки user-flows → REQ. Сейчас — только структура.
> Стиль API: **REST route handlers** (закрыто Q-029) — стандартный REST через `app/api`,
> сознательно ради будущего внешнего/мобильного API, а не Server Actions.

## Соглашения
- Транспорт: Next.js App Router, REST route handlers (`app/api/**/route.ts`).
- Все защищённые эндпоинты требуют аутентификации (ADR-0005) и tenant-scope по osiId (ADR-0006).
- Формат ответа/ошибок: `{ data }` / `{ error: { code, message } }`.
- Валидация входа: zod-схемы на границе route handler.

## Контракты (заполнить)

Шаблон записи:
```
### <METHOD> /api/<path>
- Назначение: <что делает> (REQ-XXX)
- Доступ: <роли> (user-roles.md)
- Вход: <схема>
- Выход: <схема>
- Ошибки: <коды>
```

## Реализовано (срезы 1–3 MVP)

Все ответы — `{ data }` / `{ error: { code, message } }`. Вход валидируется zod на границе.
Защищённые эндпоинты требуют cookie-сессии; председательские — роль CHAIRMAN в активной ОСИ.

### Auth (ADR-0005)
| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| POST | `/api/auth/otp/request` | Отправить одноразовый код: `{ identifier }` — телефон или email, канал определяется автоматически (REQ-005/006, `auth-email.md`); legacy `{ phone }` принимается. Rate-limit по идентификатору/IP (NFR-054) | публично |
| POST | `/api/auth/otp/verify` | Проверить код `{ identifier, code }` → сессия; первый вход создаёт аккаунт без ролей (REQ-007) | публично |
| POST | `/api/auth/login` | Вход председателя (email+пароль) | публично |
| POST | `/api/auth/logout` | Завершить сессию | сессия |
| GET | `/api/auth/me` | Текущий пользователь, активная ОСИ, роли | сессия |
| POST | `/api/auth/switch-osi` | Сменить активную ОСИ (REQ-004) | сессия (роль в ОСИ) |

### Онбординг (REQ-010..013, через forTenant)
| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| POST | `/api/osi` | Создать ОСИ (создатель → CHAIRMAN, Q-051) | сессия |
| GET/POST | `/api/buildings` | Список/создание домов активной ОСИ | CHAIRMAN |
| GET/POST | `/api/apartments` | Квартиры дома (`?buildingId=`) / создание | CHAIRMAN |
| POST | `/api/residents` | Привязать жителя к квартире (User+RESIDENT+Occupant) | CHAIRMAN |

### Уведомления (срез 7, REQ-100..105)
| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| GET | `/api/notifications` | Лента (30 последних) + счётчик непрочитанных | член ОСИ |
| POST | `/api/notifications/read` | `{id}` — одно / `{}` — все; только свои | член ОСИ |
| POST | `/api/push/subscribe` | Сохранить push-подписку устройства (upsert по endpoint) | сессия |
| DELETE | `/api/push/subscribe` | Удалить подписку `{endpoint}` | сессия |

### Платежи (REQ-030/033..035, payments-online.md, ADR-0010)
| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| POST | `/api/payments` | Ручной ввод платежа председателем (REQ-030) | CHAIRMAN |
| POST | `/api/payments/checkout` | Онлайн-оплата текущего долга жителем через симулятор эквайринга (демо-режим): `{ method: "test_card" \| "test_qr", expectedAmount?: number }` → `{ success, alreadyPaid?, gatewayRef?, amount? }` либо `{ error }` — `INSUFFICIENT_FUNDS` (402, симулированный отказ) или `AMOUNT_CHANGED` (409, долг изменился с момента показа кнопки — см. `currentAmount` в тексте сообщения) (REQ-034/036) | член ОСИ (житель) |

### Служебное
| GET | `/api/health` | Живость процесса + доступность БД (для Docker healthcheck) | публично |
