# ADR-0003: Self-hosted PostgreSQL на VPS в РК

- **Статус:** Accepted
- **Дата:** 2026-07-01
- **Контекст решения:** NFR-001, NFR-002

## Контекст и проблема
Жёсткое требование: данные физически на территории Казахстана. Это исключает managed-БД в
зарубежных облаках и напрямую определяет способ хранения.

## Рассматриваемые альтернативы
1. **Managed Postgres (Supabase / Neon / RDS)** — быстро, но данные вне РК → нарушает NFR-001.
2. **Self-hosted Postgres в Docker на VPS у казахстанского провайдера.**
3. **Self-hosted иная СУБД (MySQL/…)** — без выигрыша, ломает связку с Prisma/экосистемой.

## Сравнение (за / против)
| Критерий | Managed | Self-host Postgres (РК) | Иная СУБД self-host |
|---|---|---|---|
| Data residency (РК) | ❌ | ✅ | ✅ |
| Простота эксплуатации | высокая | средняя (наша ответственность) | средняя |
| Стоимость | подписка | VPS | VPS |
| Экосистема/Prisma | ок | отличная | хуже |
| Контроль/бэкапы | у провайдера | у нас (плюс и минус) | у нас |

## Решение
**Self-hosted PostgreSQL в Docker-контейнере** на VPS казахстанского провайдера, рядом с
приложением. Бэкапы — наша ответственность (см. NFR-060, Q-024). Провайдер VPS — Q-022.

## Последствия
- **Плюсы:** соответствие data residency, полный контроль, единый Docker-стек.
- **Минусы:** сами отвечаем за бэкапы, обновления, отказоустойчивость.
- **Что сложнее:** HA/репликация — на нас (отложено; сначала бэкапы + восстановление).
- **Влияние:** NFR-060 (бэкапы), Q-022 (провайдер), Q-024 (политика бэкапов), ADR-0006 (мультитенант в этой БД).
