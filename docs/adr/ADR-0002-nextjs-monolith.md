# ADR-0002: Next.js как монолитный fullstack-стек

- **Статус:** Accepted
- **Дата:** 2026-07-01
- **Контекст решения:** NFR-010, NFR-011, NFR-020, NFR-050

## Контекст и проблема
Нужен стек, который один разработчик может быстро развивать и поддерживать, легко разворачивать
в Docker и позже масштабировать горизонтально, при этом self-hosted (data residency).

## Рассматриваемые альтернативы
1. **Next.js (App Router) fullstack** — фронт + API-routes в одном проекте, TS everywhere.
2. **Раздельные фронт (React/Vue) + бэкенд (NestJS/Express/FastAPI)** — два проекта.
3. **Микросервисы** — несколько сервисов.

## Сравнение (за / против)
| Критерий | Next.js монолит | Фронт+бэк раздельно | Микросервисы |
|---|---|---|---|
| Простота (1 разработчик) | высокая | средняя | низкая |
| Один язык (TS) | да | зависит | зависит |
| Скорость разработки | высокая | средняя | низкая |
| Гориз. масштабирование | да (stateless + PgBouncer) | да | да |
| Операционная нагрузка | низкая | средняя | высокая |
| Self-host в Docker | просто | средне | сложно |

## Решение
**Next.js (App Router, TypeScript)** как единый fullstack-монолит. PostgreSQL self-hosted в Docker,
Prisma ORM (см. ADR-0004), HTTPS через **Nginx** + Let's Encrypt (certbot), всё через Docker Compose.
Масштабирование позже — несколько stateless-инстансов Next.js за балансировщиком + PgBouncer.

Reverse-proxy: **Nginx** (Q-026 закрыт) — выбран за счёт большей привычности/гибкости конфигурации,
несмотря на более ручную настройку certbot по сравнению с авто-HTTPS у Caddy.

## Последствия
- **Плюсы:** один язык/репозиторий, быстрый цикл, простой деплой, типобезопасность end-to-end.
- **Минусы:** связанность фронта и бэка; при сильном росте команды монолит может стать узким местом.
- **Что сложнее:** независимое масштабирование отдельных доменов (приемлемо на текущем этапе).
- **Влияние:** ADR-0003 (Postgres self-host), ADR-0004 (Prisma), ADR-0005 (auth self-host).
