# ADR-0007: Модель госинтеграций — API-медиатор, не самостоятельная аккредитация

- **Статус:** Accepted
- **Дата:** 2026-07-01
- **Контекст решения:** Q-039, gov-integrations.md, features.md (Тир 2, блоки C/E)

## Контекст и проблема
Тир 2 продукта (легитимные электронные голосования собственников + доступ к госбазам ГБД ФЛ/
Регистр недвижимости + биометрия) по закону возможен только для аккредитованного «объекта
информатизации в сфере ЖКХ» (приказ № 172), а для вызова продуктивных API Smart Bridge ИС
обязана пройти испытания на соответствие требованиям ИБ (**ст. 49 Закона РК «Об информатизации»,
ГТС**). Нужно решить, как соло-разработчик получает доступ к Тир 2.

## Рассматриваемые альтернативы
1. **A. Самостоятельная аккредитация** — пройти ГТС самим, стать объектом информатизации ЖКХ.
2. **B. API-медиатор / white-label** — партнёрство с уже аккредитованным объектом; мы —
   обработчик ПДн по поручению поверх его инфраструктуры.
3. **C. Отказаться от Тир 2** — жить только в Тир 1 (коммуникация + учёт + автоотчёт).

## Почему альтернатива A закрыта для соло (ключевое)
ГТС недостижим организационно и экономически:
- **Организация (СТ РК ИСО/МЭК 27001):** нужен выделенный офицер ИБ (CISO), квалифицированные
  сисадмины, служба техподдержки. Один человек не может быть разработчиком, безопасником,
  аудитором и директором одновременно.
- **Документы:** 30+ регламентов (политика ИБ, реагирование на инциденты, физзащита серверов,
  управление доступом) — требуют профильного консалтинга.
- **Инфраструктура:** не зарубежный хостинг (AWS/DO/Hetzner), а защищённый **ЦОД Tier III в РК**,
  сертифицированные СЗИ/шифрование, WAF, подключение к **ЕШДИ** (Единый шлюз доступа к Интернету)
  и **SOC** (Центр анализа и реагирования на компьютерные инциденты).
- **Стоимость:** аудит/подготовка ~1,5–3 млн ₸ + пошлина ГТС 2–5 млн ₸ + защищённый хостинг+СЗИ
  от 300 000 ₸/мес → ~$15 000–20 000 только на комплаенс.
- **Срок:** 6–12 месяцев с нуля.

→ Для соло-разработчика без инвестиций путь A экономически закрыт.

## Решение
- **Тир 1 (Фазы 1–2) — строим сами**, аккредитация не нужна (коммуникация, учёт, автоотчёт из
  выписки Kaspi, кабинет). Это самодостаточный продукт с полной ценностью.
- **Тир 2 (Фаза 3) — модель B (API-медиатор):** наше приложение = удобный фронтенд/UX; запросы к
  госданным и легитимным голосованиям идут не напрямую в Smart Bridge, а в **API аккредитованного
  партнёра**, у которого ГТС уже пройден. Юридически партнёр — оператор ПДн верхнего уровня, мы —
  третья сторона, **обрабатывающая по поручению**. Экономика: фикс/процент за запрос
  (ориентир ~5 ₸ за проверку ИИН/квартиры), закладывается в подписку.

## Практические следствия для реализации
- **Архитектурная развязка:** Тир 1 **не зависит** от Тир 2. Доступ к Тир 2 — через **сменяемый
  adapter** партнёрского API (интерфейс `GovVerificationProvider`), чтобы не захардкодить одного
  партнёра и иметь возможность сменить его.
- **Правовой статус:** мы — «обработчик ПДн по поручению» (договор поручения с партнёром);
  собственные обязанности оператора ПДн для данных Тир 1 сохраняются (уведомление МЦРИАП,
  регламент, ответственное лицо — NFR-051, gov-integrations.md §3).
- **Юнит-экономика:** per-request-стоимость партнёра должна укладываться в подписку (платформы
  закладывают ~15–30 ₸/квартира/мес) — смоделировать до подписания.

## Последствия
- **Плюсы:** экономит ~$15–20k и 6–12 мес; Тир 1 запускается без гос-барьера; сохраняем фокус на
  UX-дифференциаторе, который весь в Тир 1 (полный контроль).
- **Минусы / риски (главное — управлять договором):**
  - 🔴 **Зависимость от API партнёра, особенно если это конкурент** (Управдом/e-Shanyraq): риск
    поднятия цены, отключения, копирования наших фич, доступа к нашим клиентам/данным.
  - **Митигации:** (1) предпочесть **нейтрального аккредитованного оператора** (финтех/идентити-
    оператор, не прямой ЖКХ-конкурент), а не Управдом; (2) сменяемый adapter — не завязываться на
    одного; (3) договорные защиты: запрет копирования фич, фиксация цены, SLA, exit-условия,
    «наши данные — наши»; (4) минимизировать передаваемое партнёру (только необходимое для
    проверки, не вся клиентская база).
- **Что сложнее:** Тир 2 никогда не будет полностью «нашим» — часть цепочки всегда у партнёра.
  Приемлемо: Тир 1 самодостаточен, Тир 2 подключаем при появлении спроса/бюджета.
- **Влияние:** Q-039 решён в части модели (B). Новый открытый вопрос **Q-043** — выбор конкретного
  партнёра (нейтральный оператор vs конкурент) + договорные защиты. gov-integrations.md обновить
  (модель A помечена как закрытая для соло).
