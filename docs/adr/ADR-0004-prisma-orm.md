# ADR-0004: Prisma как единый источник модели данных

- **Статус:** Accepted
- **Дата:** 2026-07-01
- **Контекст решения:** NFR-010, NFR-080, domain-model.md

## Контекст и проблема
Нужен один источник правды для модели данных с типобезопасностью в TS-стеке, миграциями и
низким порогом для одного разработчика.

## Рассматриваемые альтернативы
1. **Prisma ORM** — schema.prisma как единый источник, генерируемый типобезопасный клиент, миграции.
2. **Drizzle ORM** — TS-first, ближе к SQL, лёгкий.
3. **Голый SQL / query-builder (Kysely)** — максимум контроля, больше ручной работы.

## Сравнение (за / против)
| Критерий | Prisma | Drizzle | SQL/Kysely |
|---|---|---|---|
| Типобезопасность | высокая | высокая | средняя |
| Единый источник модели | schema.prisma | TS-схема | нет (миграции вручную) |
| Миграции | встроены | есть | вручную/отдельно |
| Порог входа (1 чел.) | низкий | средний | выше |
| Контроль над SQL | средний | высокий | максимум |
| Совместимость с мультитенант (RLS/схемы) | зависит от ADR-0006 | гибче для raw SQL | максимум |

## Решение
**Prisma ORM.** `schema.prisma` — единый источник модели, миграции и типобезопасный доступ.
Совместимость с выбранной моделью мультитенантности проверить при закрытии **ADR-0006**
(особенно если выбор падёт на Postgres RLS или схему-на-тенанта — там у Prisma есть ограничения).

## Последствия
- **Плюсы:** быстрая разработка, типы end-to-end, встроенные миграции, хорошая экосистема.
- **Минусы:** меньше контроля над сложными запросами; ограничения при некоторых мультитенант-стратегиях (RLS/несколько схем).
- **Влияние:** зависит от ADR-0006; domain-model.md → schema.prisma.
