# Деплой в продакшен (первый клиент)

> Статус: ACTIVE · Дата: 2026-07-15 · Контекст: NFR-001 (данные — физически в РК), Q-022.
> Весь рантайм уже упакован: `docker compose up -d --build` поднимает Postgres + миграции +
> PgBouncer + Next.js + Nginx (HTTPS). Этот документ — что купить и в каком порядке включать.

## 1. Что покупает/регистрирует владелец (≈30–60 минут + ожидание DNS)

| # | Что | Где | Ориентир цены | Зачем |
|---|---|---|---|---|
| 1 | **VPS в Казахстане** — 2 vCPU / 4 ГБ RAM / 40+ ГБ NVMe, Ubuntu 24.04 LTS, публичный IPv4 | ps.kz (Cloud/VPS) или hoster.kz | ~6–12 тыс ₸/мес | data residency (NFR-001): managed-облака запрещены |
| 2 | **Домен** (например, `fixly.kz`) | там же (ps.kz/hoster.kz) | ~2–5 тыс ₸/год | HTTPS (REQ-062), адрес для клиента, отправка почты |
| 3 | **Транзакционная почта** — аккаунт Resend (3000 писем/мес бесплатно) или Brevo (300/день) | resend.com / brevo.com | бесплатно на старте | доставка кодов входа по email (REQ-006). ⚠️ Требует домена (п. 2) — без верификации домена прод-отправка невозможна (Resend без домена шлёт только на свой адрес) |
| 4 | **SMS-шлюз** — аккаунт Mobizon, режим общей подписи (юрлицо/альфа-имя НЕ нужны, Q-030 решён 2026-07-18) | mobizon.kz | бесплатно (SMS по КЗ с общей подписью) | доставка кодов входа по телефону (REQ-006), не ждёт домена — можно включить раньше почты |
| 5 | **Приватный репозиторий GitHub** + URL для push | github.com | бесплатно | доставка кода на сервер, CI уже написан (`.github/`) |

DNS после покупки: `A`-запись домена → IP VPS; записи SPF/DKIM/DMARC — скопировать из
кабинета почтового сервиса (без них письма с кодами уходят в спам — критично для входа).

Отложено сознательно: реальный SMS-шлюз Mobizon — новый аккаунт требует активации
направления «Казахстан» (по факту это требует ИП/юрлица у ЛЮБОГО провайдера, не только
Mobizon — разведка 2026-07-18); именная подпись SMS «Fixly» — отдельный апгрейд после
этого. До тех пор телефон входит через **Telegram-бота** (REQ-009, telegram-otp.md) —
рабочий канал, проверен живьём 2026-07-18. Реальный эквайринг (REQ-030) — работает
демо-симулятор.

## 2. Установка на VPS (≈20 минут, по SSH)

```bash
# 1. Docker + compose-плагин
curl -fsSL https://get.docker.com | sh

# 2. Код (монорепо: сайт в web/, приложение в app/ — деплоится только web/)
git clone <URL приватного репозитория> /opt/fixlypwa && cd /opt/fixlypwa/web

# 3. Секреты
cp .env.example .env && nano .env
```

Обязательные значения `.env` для прода:

| Переменная | Значение |
|---|---|
| `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `APP_SUPERADMIN_PASSWORD` | длинные случайные (`openssl rand -base64 24`) |
| `DATABASE_URL` / `DIRECT_URL` | по образцу из `.env.example` (pgbouncer/postgres — имена сервисов compose) |
| `EMAIL_PROVIDER` | `smtp` |
| `SMTP_HOST/PORT/USER/PASS`, `MAIL_FROM` | из кабинета Resend/Brevo; `MAIL_FROM="Fixly <no-reply@домен>"` |
| `OTP_DEV_ECHO` | `0` (⚠️ обязательно: с `1` любой получает чужой код в ответе API) |
| `SMS_PROVIDER` | `console` (реальный шлюз ждёт активации аккаунта Mobizon — см. §1) |
| `PHONE_OTP_CHANNEL` | `telegram` (REQ-009 — рабочий канал телефона до Mobizon) |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_BOT_USERNAME` | из @BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | случайная строка (`openssl rand -hex 24`), тот же секрет — в `setWebhook` ниже |
| `MOBIZON_API_KEY` | из личного кабинета mobizon.kz (готово к переключению, когда Mobizon активирует направление) |

```bash
# 4. Запуск (postgres → миграции+пароли ролей → pgbouncer → app → nginx)
docker compose up -d --build

# 5. HTTPS: сертификат Let's Encrypt вместо self-signed (README §«Продакшн: HTTPS»):
#    A-запись должна уже указывать на VPS; затем certbot webroot в том nginx_certs.

# 6. Telegram-вебхук (REQ-009) — один раз, после HTTPS:
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -d "url=https://<домен>/api/telegram/webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"

# 7. Суперадмин платформы (после самостоятельной регистрации владельца по email на сайте):
docker compose exec app npx tsx scripts/make-superadmin.ts <телефон или email владельца>
```

## 3. Онбординг первого клиента (без участия разработчика)

1. Председатель открывает `https://домен/register` → карточка «Председатель» → email → код
   из письма → создаёт ОСИ, дом, квартиры (REQ-007/Q-051).
2. Жителей добавляет по email (кнопка «Житель» у квартиры) — те входят кодом из письма.
3. Владелец в `/admin` выставляет дому подписку (TRIAL/ACTIVE, REQ-111).

## 4. После запуска (первая неделя)

- **Бэкапы БД**: cron на VPS — `docker compose exec -T postgres pg_dump -U postgres fixlypwa | gzip > /backup/$(date +%F).sql.gz` (+ выгрузка за пределы VPS). Скрипта в repo пока нет — [TBD].
- **Мониторинг**: `GET /api/health` — готовый endpoint для UptimeRobot и т.п.
- Web Push (опционально): `npx web-push generate-vapid-keys` → три переменные в `.env`.

## 5. Известные ограничения прод-запуска

- Вход/приглашение только по email (телефон вернётся с SMS-шлюзом, Q-030).
- Онлайн-оплата — демо-симулятор (ADR-0010), о чём UI явно предупреждает (REQ-035).
