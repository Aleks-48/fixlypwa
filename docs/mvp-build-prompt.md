## 🎯 Директива (короткая версия для старта)

## 1. Роль и режим работы

## 3. Что строим — Фаза 1 (первый рабочий срез Тир 1)
Коммуникация + кабинет + вход. Снимает нагрузку председателя и головную боль жителей, **без**
гос-барьера и без тяжёлого учёта.

## 4. Скоуп (жёстко)
**В MVP (Фаза 1):**
- Вход: житель — телефон + OTP; председатель — телефон/email + пароль (REQ-001, ADR-0005).
- Онбординг: ОСИ → дом(а) → квартиры → жители/собственники (REQ-010..013). Активная ОСИ в сессии.
- Коммуникация (features.md блок B / F-A..F-G): объявления (адресные, отметки о прочтении),
  заявки со статусом и тредом, инфо-раздел, push-уведомления.
- Быстрые опросы (lite, не юридические) — если укладывается; иначе перенести.
- Кабинет жителя (REQ-050/052): профиль, привязка к квартире, реквизиты для оплаты (static).
- PWA (REQ-060..062, NFR-040/041): manifest, service worker, офлайн-просмотр, установка, HTTPS.
- UI на русском (REQ-080).

**Вне MVP (не начинать):**
- Учёт/начисления/платежи/расходы/**автоотчёт** — это Фаза 2 (Тир 1, следующий срез).
- Легитимные голосования, госбазы, Digital ID, биометрия — **Тир 2** за аккредитацией (ADR-0007).
- Онлайн-приём платежей/эквайринг. Замена WhatsApp-чата.

## 5. Definition of Done (проверяемо — без этого MVP не готов)
1. `npm run typecheck` · `lint` · `test` — **зелёные**; TS strict без `any`-заглушек.
2. `docker compose up` поднимает всё (Next.js + Postgres + PgBouncer + Nginx/HTTPS); приложение
   открывается по HTTPS, **PWA устанавливается** («Add to Home Screen»), офлайн-просмотр ранее
   загруженных данных работает.
3. **RLS доказан интеграционным тестом**: тенант А не видит данные тенанта Б; запрос вне
   `forTenant` → 0 строк (deny-by-default). Идентичность (osi/users/sessions/user_osi_role) вне RLS.
4. **E2E зелёные (Playwright)** для ключевых флоу: (а) онбординг ОСИ→дом→квартира→житель;
   (б) вход жителя по OTP; (в) объявление → отметка о прочтении; (г) заявка → смена статуса.
5. **Безопасность:** OTP с rate-limit (NFR-054, REQ-091); токены сессий хранятся хешем (ADR-0005);
   проверка прав на сервере, не только в UI (REQ-003); ПДн только в РК-инфраструктуре (NFR-051).
6. **CI (GitHub Actions):** lint + typecheck + test на каждый PR; миграции применяются в CI на
   чистую БД (`prisma migrate deploy`).
7. **Lighthouse PWA** ≥ 90 (installable, offline, a11y).
8. `README.md`: как поднять локально одной командой; `.env.example` заполнен.

## 6. Скиллы и стандарты (чем руководствоваться на каждом шаге)
- **Мультитенант-безопасность (критично):** доступ к tenant-таблицам ТОЛЬКО через `forTenant(osiId, fn)`
  (паттерн из `spikes/rls-prisma/src/tenant.ts` через Prisma `$transaction` + `set_config(..., true)`).
  Никогда не хардкодить/прокидывать `osiId` в обход сессии. RLS — deny-by-default.
- **Type-safety end-to-end:** Zod-валидация на границе route handlers (`app/api/**`), Prisma-типы
  внутрь, единый формат ответа `{ data }` / `{ error: { code, message } }` (api-contracts.md).
- **Тестовая пирамида:**
  - unit (Vitest) — доменная логика и права (напр. статусы Charge, матрица доступа user-roles.md);
  - integration — RLS-изоляция, миграции, репозитории (Testcontainers/поднятая Postgres);
  - e2e (Playwright) — ключевые пользовательские флоу (§5.4).
- **Безопасность:** серверная авторизация по ролям (REQ-003, user-roles.md), rate-limit OTP,
  защита от перебора кода, secure cookies (HttpOnly/SameSite/Secure), секреты в `.env` вне репо.
- **PWA:** `@ducanh2912/next-pwa` (не заброшенный `next-pwa`; альтернатива Serwist), продуманная
  стратегия кэша (что офлайн — уточнить при реализации SW), корректный manifest/иконки.
- **UX — это продукт (features.md §0):** mobile-first, минимум шагов/полей, быстрый онбординг
  «без беготни», понятные формулировки. Дифференциатор — удобство, а не фичи.
- **Доступность:** WCAG 2.1 AA (семантика, фокус, контраст, клавиатура).
- **i18n-ready:** тексты вынесены (ru сейчас; каз. — для отчётов позже, REQ-081); не хардкодить строки.
- **Наблюдаемость:** структурные логи; заготовка под Grafana+Loki (NFR-070), без утечки ПДн в логи.
- **Качество кода (NFR-080):** ESLint + Prettier + TS strict с первого коммита; осмысленные коммиты.

## 7. Порядок (вертикальные срезы, каждый — с тестами)
1. **Скелет + инфра.** Next.js App Router, TS strict, ESLint/Prettier/Vitest/Playwright,
   `docker-compose.yml` (Next.js + Postgres + PgBouncer transaction + Nginx/Let's Encrypt),
   Prisma подключён через PgBouncer, `forTenant`-обёртка перенесена из спайка, healthcheck,
   один smoke-тест. Применить существующие миграции (`init` + `rls_policies`).
2. **Auth (ADR-0005).** Телефон+OTP (SMS-заглушка/провайдер), самописные сессии (хеш токена,
   таблица `Session`, активная ОСИ), rate-limit OTP. Unit + e2e входа.
3. **Онбординг.** CRUD ОСИ/дом/квартиры/жители через `forTenant`. **Integration-тест RLS-изоляции.**
4. **Коммуникация.** Объявления + прочтения, заявки + статусы + тред, инфо-раздел, push. E2E флоу.
5. **Кабинет жителя + PWA.** Профиль/реквизиты, manifest, service worker, офлайн, установка. Lighthouse.
6. **Полиш.** a11y-проверка, CI (GitHub Actions), `README`/`.env.example`, `/code-review` + `/security-review`.

## 8. Guardrails (нарушение = стоп)
- Нет спеки → не пишем код фичи (SDD); мелкое уточнение фиксируем в `/docs` со ссылкой.
- Не обходить RLS, не ходить в tenant-таблицы вне `forTenant`, не подключаться суперпользователем БД.
- Managed-облака запрещены (data residency, NFR-001) — только self-host.
- Не начинать Тир 2 (голосования собрания, госбазы, биометрия).
- Секреты/ПДн — не в репозиторий и не в логи.
