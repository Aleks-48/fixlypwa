## Этап 3 — полудеплой-тесты (генеральная репетиция, ~0.5–1 день)

Локально, но В ПРОД-РЕЖИМЕ — тот же артефакт, что поедет на VPS:

1. `docker compose up -d --build` с прод-переменными: `EMAIL_PROVIDER=smtp` (Resend,
   тест-режим — письма на адрес владельца аккаунта), `OTP_DEV_ECHO=0`, полный стек
   Postgres+PgBouncer+Next+Nginx по HTTPS (self-signed).
2. Сквозные сценарии руками: регистрация председателя по email-коду (РЕАЛЬНОЕ письмо) →
   создание ОСИ → **импорт реального реестра 73 помещений** → тариф → начисление →
   уведомления → отчёт №163 → вход жителя.
3. Проверка бэкапа: `scripts/` pg_dump снимает и восстанавливается.
4. *(опция)* ngrok-туннель — показать председателю «Центрального 2Б» до покупки VPS и
   собрать обратную связь на реальных данных.

## Этап 4 — полноценный деплой (по deploy.md, ~0.5 дня работы + ожидание DNS)

Покупки Рахима (§1 deploy.md): **домен** (можно уже сейчас — разблокирует полноценный
Resend независимо от VPS) и **VPS РК** (ps.kz/hoster.kz, 2 vCPU/4 ГБ).

1. DNS: A-запись → IP VPS; верификация домена в Resend → SPF/DKIM/DMARC из кабинета →
   `MAIL_FROM=no-reply@<домен>` (тест-режим снимается, письма всем получателям).
2. VPS: Docker → `git clone` (нужен remote из 1.3) → `.env` прод-секреты
   (`openssl rand -base64 24`; таблица в deploy.md §2) → `docker compose up -d --build` →
   certbot HTTPS.
3. Прод-смоук: регистрация по email-коду на чужой ящик, Telegram-код, health, PWA installable.
4. `make-superadmin` Рахиму → онбординг первого клиента: председатель регистрируется,
   импорт реестра, первый тариф и начисление.
5. Бэкапы по крону (Q-024: ежедневный pg_dump, ротация 30 дней) + минимальный мониторинг
   (healthcheck; Grafana/Loki из Q-025 — потом, не блокер).
