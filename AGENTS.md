# Проект: Управление ОСИ — PWA

## Что это
PWA-приложение для управления ОСИ (объединение собственников имущества) в Казахстане (Кокшетау).
Изначально анализировали B2G-модель (гос. сектор), но отклонили — прямая конкуренция с
государственной платформой E-Shanyraq. **Выбрана модель B2B2C SaaS**: продаём подписку
председателям ОСИ, они управляют домом, жители видят начисления/отчёты.

Ключевой аргумент продажи: автоматическая генерация ежемесячных отчётов для председателей
(сейчас делают вручную/в Excel — большая боль).

## Требования (жёсткие ограничения)
- **Данные должны физически храниться на территории Казахстана.** Managed-облака вроде
  Supabase/Vercel/AWS — исключены. Нужен self-hosted backend на VPS у казахстанского провайдера.
- **Стек должен быть максимально простым** — минимум разных технологий, монолит вместо
  микросервисов. Приоритет: скорость разработки одним человеком + лёгкость поддержки.
- Должно легко разворачиваться (Docker) и **легко масштабироваться горизонтально** в будущем.
- Современные стандарты PWA: офлайн-режим, "Add to Home Screen", HTTPS обязателен.

## Выбранный стек
- **Next.js (App Router)** — фронтенд + бэкенд (API routes) в одном проекте, TypeScript everywhere.
- **PostgreSQL** — self-hosted (НЕ managed), в Docker-контейнере на том же VPS.
- **Prisma ORM** — единый источник модели данных (schema.prisma), миграции, типобезопасность.
- **Самописные сессии по паттерну Lucia** (opaque token + таблица Session в Prisma) — Lucia
  как пакет deprecated с 2026, теперь это learning resource, не библиотека. Альтернатива на
  примете — Auth.js v5 или better-auth. См. `docs/adr/ADR-0005-auth.md` (ревизия).
- **@ducanh2912/next-pwa** (поддерживаемый форк; оригинальный `next-pwa`/shadowwalker
  заброшен) — service worker, manifest.json, офлайн-кэш. Альтернатива на будущее — Serwist.
- **Docker Compose** — Next.js + Postgres + Nginx/Caddy (для HTTPS через Let's Encrypt) одним `docker-compose up`.
- Для будущего масштабирования: PgBouncer (connection pooling) + возможность поднять несколько
  инстансов Next.js за балансировщиком.

## Подход к разработке — SDD, не вайб-кодинг
Работаем по Spec-Driven Development:
1. Сначала описываем фичу в `/docs/specs` и `/docs/requirements` (нумерованные, тестируемые требования, напр. REQ-042).
2. Потом пишем код, ссылаясь на номера требований.
3. Архитектурные решения фиксируем в `/docs/adr` (Architecture Decision Records) — почему выбрали X, а не Y.

**Не начинай писать код фичи, пока для неё нет хотя бы краткой спеки.** Если пользователь просит
код без спеки — предложи сначала кратко описать требование.

## Структура репозитория (монорепо с 2026-07-19)
```
/docs                    — ОБЩИЕ спеки/ADR/требования на оба клиента
  /specs               — vision, domain model, user flows, api contracts, mobile-app
  /adr                 — architecture decision records
  /requirements        — functional.md, non-functional.md
  /reference           — приказ №163 (PDF), образцы отчётов
/web                     — САЙТ: Next.js (App Router) + Prisma + docker-compose + тесты
  /prisma/schema.prisma — единый источник модели данных
  /src                 — код сайта (src/app — App Router, src/lib — сервисы)
  /docker, docker-compose.yml, .env — весь деплой-стек живёт здесь (cd web && docker compose up)
  /scripts             — make-superadmin, seed, бэкапы
/app                     — ПРИЛОЖЕНИЕ: Flutter (бывший отдельный репо fixly, влит subtree'ом,
                           история сохранена; старый C:\Projects\fixly — архив, НЕ редактировать)
AGENTS.md                — этот файл
README.md                — карта монорепо
```
⚠️ Все npm/prisma/vitest/playwright-команды сайта выполняются ИЗ web/ (`cd web`),
flutter-команды — из app/. НЕ путать app/ (Flutter) с web/src/app (Next.js App Router).

## Инструменты качества (все бесплатные, open-source)
- TypeScript strict mode — включено в tsconfig.json с самого начала.
- ESLint + Prettier — лint и форматирование.
- Vitest — unit/интеграционные тесты.
- Git + GitHub — репозиторий как источник истины.

## Рекомендованные MCP/инструменты для эффективности
- **Serena MCP** (github.com/oraios/serena) — символьное понимание кода (LSP), экономит токены
  на чтении файлов, точнее рефакторинг. Подключить через:
  `Codex mcp add serena -- uvx --from git+https://github.com/oraios/serena serena start-mcp-server --context ide-assistant --project "$(pwd)"`
- Кастомные skills под домен ОСИ — создавать через встроенный skill-creator по мере необходимости,
  НЕ тянуть сторонние маркетплейсы скиллов без разбора (риск supply-chain атак).

## Текущий статус проекта (обновлено 2026-07-14)
Спеки/ADR/реестр вопросов — в `/docs` (см. `docs/README.md`, `docs/needs.md` — чек-лист
зависимостей). Позиционирование определено: полный функционал уровня Управдома, дифференциатор —
удобство (`docs/specs/features.md`). Тир 1 (Фазы 1–2: коммуникация + учёт + автоотчёт) — без
гос-барьера, строим сами. Тир 2 (легитимные голосования, госбазы) — через партнёрство
(ADR-0007), не своя аккредитация.

**MVP Тир 1 собран и работает** (срезы 1–9, 14–15 + онлайн-оплата):
- Инфраструктура: docker-compose (Next.js + Postgres + PgBouncer + Nginx), TS strict,
  ESLint/Prettier, PWA (@ducanh2912/next-pwa), RLS-мультитенантность через `forTenant()`
  (ADR-0006), самописные сессии: OTP жителя + email/пароль председателя (ADR-0005).
- Функционал: онбординг (ОСИ/дома/квартиры/жители); коммуникация (объявления, заявки с фото,
  опросы); финансы (тарифы, начисления, платежи, расходы, банковские счета); отчёты по форме
  приказа № 163 (месяц/квартал/год, публикация жителям со скрытием ПДн); уведомления in-app +
  Web Push; админка платформы (ADR-0008); маркетплейс мастеров (ADR-0009); онлайн-оплата
  жителем в демо-режиме — симулятор эквайринга (ADR-0010, REQ-033..036,
  `docs/specs/payments-online.md`).
- Тесты: 20 unit + 40 integration (Vitest, требуют поднятого Postgres) + e2e-сценарии
  (Playwright), все зелёные.

Следующие шаги: полевая валидация с председателями Кокшетау (Q-036/Q-042), реальные образцы
Excel с квартирами и выписки Kaspi Pay (Q-012/Q-013), деплой на VPS в РК (data residency,
Q-022), SMS-шлюз для OTP (Q-030).
