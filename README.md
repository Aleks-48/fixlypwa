# Fixly — управление ОСИ (Кокшетау)

B2B2C SaaS для ОСИ: председатель управляет домом, жители видят начисления и отчёты.
Монорепо (с 2026-07-19):

| Папка | Что | Как запустить |
|---|---|---|
| [`web/`](web/README.md) | Сайт: Next.js + Prisma + Postgres (docker-compose) | `cd web && npm install && docker compose up -d postgres pgbouncer && npm run dev` |
| `app/` | Мобильное приложение: Flutter (Android/iOS/web) | `cd app && flutter run` |
| `docs/` | Спеки, ADR, требования (SDD) — общие на оба клиента | читать `docs/README.md` |

Подробности запуска сайта — [web/README.md](web/README.md). Деплой — [docs/deploy.md](docs/deploy.md).

## Запуск на этом компьютере

Откройте `START_FIXLY.bat` в корне проекта. Он запускает Docker Desktop при необходимости,
PostgreSQL с сохранением данных, делает резервную копию, применяет миграции, запускает
ngrok и сайт/API, затем регистрирует Telegram webhook. Сайт открывается по адресу
`http://127.0.0.1:3000`. Логи фоновых процессов — в `.local-run/`.

Нужны Node.js/npm, Docker Desktop, заполненный `web/.env`, `web/ngrok.exe` и
`web/ngrok.yml` с туннелем `frontend` на порт 3000. Секреты остаются в локальных файлах.
Повторный запуск перезапускает сайт этого проекта и использует работающий ngrok.
Если порт занят другим проектом, запуск останавливается с сообщением.

Приложение открывается на телефоне самостоятельно. Батник поддерживает его сервер и
обновляет `API_BASE_URL` в **исходниках** `app/.env`; уже установленный APK хранит адрес
с момента сборки. Если адрес ngrok изменился, приложение необходимо пересобрать и установить.
Батник не собирает Flutter. Для изолированной копии друга используется `START_TESTER.bat`.

Процесс разработки (спека → код) и правила — [CLAUDE.md](CLAUDE.md).

История: сайт разрабатывался в этом репозитории с нуля; Flutter-приложение влито из
отдельного репозитория `fixly` через git subtree (история коммитов сохранена).
