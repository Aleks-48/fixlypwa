# Fixly — независимая проверка

Это исходники сайта (`web/`), Flutter-приложения (`app/`) и документация (`docs/`). Начните с сайта: мобильному приложению нужен этот же сервер. Архив не содержит рабочую БД, секреты, загруженные пользователями файлы или установленные зависимости.

## Быстрый запуск сайта

Нужны Node.js 22 или 24, npm и запущенный Docker Desktop с Linux-контейнерами. Для первой установки нужен интернет. Распакуйте ZIP в новую папку; не объединяйте его с другим экземпляром проекта.

В Windows запустите `START_TESTER.bat`. Либо в терминале:

```sh
cd web
node scripts/setup-tester.mjs
npm run dev -- --hostname 127.0.0.1
```

Скрипт создаёт `web/.env` со случайными локальными паролями, поднимает отдельный Compose-проект `fixly-tester` и PostgreSQL на **5545**, устанавливает зависимости через `npm ci`, применяет миграции, настраивает роли БД и создаёт синтетическое демо. Обычный файл `.env` другой установки не перезаписывается. Повторный запуск сохраняет БД. Используйте ту же распакованную папку и сохраняйте её `.env`: новая копия с новым паролем не сможет открыть старый том. При ошибке исправьте причину в консоли и повторите команду.

Откройте **http://localhost:3000**. Если порт занят, запустите `npm run dev -- --hostname 127.0.0.1 --port 3001` и откройте 3001. Если занят порт 5545, остановите предыдущий тестовый экземпляр; основная конфигурация проекта использует 5544.

| Роль | Вход |
|---|---|
| Председатель | `/login?role=chairman`, `demo@osi.kz`, пароль `demo12345` |
| Житель | `/login`, телефон `+77010000001`; одноразовый код появляется на локальной форме входа и в консоли сервера |

SMS, email, Telegram и ИИ настроены на локальные заглушки. Реальные сообщения и списания не выполняются. Push без ключей отключён. Проверяйте на вымышленных данных.

Для остановки сайта нажмите Ctrl+C. Остановить БД, сохранив данные:

```sh
docker compose -p fixly-tester -f docker-compose.tester.yml stop
```

## Автоматические проверки

Из `web/`, после setup:

```sh
npm run typecheck
npm test
npm run test:integration
npm run lint
npm run build
```

При запущенном сайте можно проверить демо-вход и импорт CSV командой `node scripts/smoke-tester.mjs`. Она проводит один синтетический платёж и проверяет повторный импорт. Для другого порта передайте URL, например `node scripts/smoke-tester.mjs http://127.0.0.1:3001`.

Интеграционные проверки используют отдельную БД `fixly_tester_test`. В сборке загружается Google-шрифт, поэтому нужен сетевой доступ. Итог проверок от 26 сентября: 78 unit, 103 integration, 21 проверка браузера; ESLint — без ошибок, 5 предупреждений. Подробности в `docs/technical-acceptance-2026-09-26.md`.

Браузерные автотесты запускаются отдельно: `npx playwright install chromium`, затем `npm run e2e`. Их наличие в архиве не означает, что они пройдены в этом срезе. Они используют БД запущенного сайта, поэтому запускайте их только в синтетическом окружении архива. Перед запуском остановите dev-сервер: Playwright должен запустить сервер со своим режимом OTP. Конфигурация — `web/playwright.config.ts`.

## Что проверить вручную

| Сценарий | Ожидаемый результат |
|---|---|
| Вход председателя и жителя в разных профилях браузера | Правильная роль и доступные разделы; выход закрывает доступ |
| Дом → квартира → житель | Данные сохраняются после обновления страницы |
| Тариф → начисление → платёж → отчёт | Суммы и остатки совпадают; отчёт доступен жителю после публикации |
| Выписка | Выбрать демо-дом, загрузить `web/tests/fixtures/bank-import-demo.csv`, проверить предпросмотр, провести и повторить импорт; повтор не создаёт платёж |
| Нераспознанные строки выписки | Явно показано, что они не проведены; расходы и несопоставленные платежи вносятся вручную |
| Заявка | Создание с фото → изменение статуса → закрытие → отзыв; второй отзыв не создаётся |
| Профиль | ФИО и язык сохраняются после обновления |
| Отказ ИИ | При выключенном провайдере сканер показывает ошибку, не выдуманный результат |
| Разные ОСИ | Участник второго ОСИ не видит документы, счета и заявки первого |
| PWA | Проверять на production-сборке: `npm run build`, `npm start`; установка и офлайн-экран. В режиме dev service worker отключён |

## Flutter

Нужны Flutter SDK и Android SDK/JDK для Android. APK в этот исходный архив не включён; отдельно подготовлен `Fixly-debug-localhost.apk` (debug, около 153 МиБ). Он настроен на `http://localhost:3000`, push отключён. Для подключения к серверу компьютера по USB/эмулятору используйте `adb reverse tcp:3000 tcp:3000`, затем установите APK. Сборка подтверждена; запуск на физическом устройстве не проверялся. Из `app/` можно собрать свою версию:

```sh
flutter pub get
```

Скопируйте `.env.example` в `.env`, затем задайте `API_BASE_URL=http://10.0.2.2:3000` для Android-эмулятора или `http://localhost:3000` для десктопа. Для реального телефона используйте IP компьютера в своей локальной сети и запустите сайт с `--hostname 0.0.0.0`; доступ через локальный firewall может потребовать настройки. Веб-версия Flutter дополнительно требует CORS_DEV_ORIGINS в web/.env.

```sh
flutter analyze
flutter run
flutter build apk --debug
```

Локальные `.env`, `android/local.properties`, ключи подписи и Firebase-конфигурация не передаются. SDK создаёт локальные служебные файлы. Физическое устройство, push и релизная подпись требуют отдельной проверки.

## Как прислать найденную ошибку

Запишите версию архива, устройство/браузер, роль, точные шаги, ожидаемый и фактический результат. Добавьте скриншот и текст ошибки из консоли без одноразовых кодов и секретов. Укажите: блокирует работу / мешает / косметика.

Известные ограничения и результаты проверок — `docs/tester-handoff-status.md`. Продукт предназначен для локального тестирования; готовность к коммерческому запуску требует отдельной приёмки и инфраструктуры.
